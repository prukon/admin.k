Постоплата (schedule_type = postpay)

Файл: /docs/documentation/postpay.html · см. также Абонементы, право type.postpay, Установка цен, Журнал, Консоль, Оплаты
Суть. Месячная оплата по факту посещений (календарный месяц, Europe/Moscow). Источник истины — шаблон lesson_packages с типом postpay + строка users_prices на тройку (user_id, team_id, new_month). Таблица назначений user_lesson_packages не используется и для postpay намеренно запрещена (валидация store назначения).
Не путать с полем user_lesson_packages.billing_month (lesson-packages § billing_month, payments § billing_month). Постоплата не пишет в ULP и не опирается на billing_month: биллинг только через users_prices. Обычные типы при установке цен получают месячный ULP (UsersPriceLessonPackageSync + FK users_prices.user_lesson_package_id) для журнала/календаря; postpay при смене с assignable снимает только неразложенный ULP.

1) Шаблон абонемента

  • Константа: LessonPackage::SCHEDULE_TYPE_POSTPAY = 'postpay'; входит в SCHEDULE_TYPES.
  • Не входит в ASSIGNMENT_SCHEDULE_TYPES — для postpay не создают ULP.
  • price_cents — стоимость одного занятия (в UI: «Стоимость за одно занятие»).
  • При store/update: duration_days = 31, lessons_count = 1 (служебные); заморозка и автосписание недоступны (freeze_enabled=false, auto_attendance_enabled=false).
  • UI: вкладка «Абонементы» / дубль в «Справочниках» — option «Постоплата» в create/edit и в фильтре типа только при lessonPackages.type.postpay.
  • Права: lessonPackages.view (раздел) + скрытое lessonPackages.type.postpay (описание: Абонементы, тип «Постоплата»; группа lessonPackages; is_visible=0; не в базовых ролях). Без права: option скрыт; store/update с schedule_type=postpay → 422 на schedule_type (кроме правки уже существующего postpay-шаблона); фильтр DataTables postpay → пусто; в select назначений ULP postpay не показывается. Карточка права — lesson-packages-type-postpay.

2) Назначение на месяц (только «Установка цен»)

  • Ручной выбор шаблона postpay в select абонемента на вкладке «по месяцам» (и при массовом apply группы) → в users_prices.lesson_package_id. Нужно lessonPackages.type.postpay (без права: пакет скрыт в каталоге, кроме уже назначенных; новый выбор → 422 на поле пакета; повторная отправка того же назначенного id — разрешена).
  • Без автопродления: назначение действует на выбранный месяц; следующий месяц нужно выставить отдельно.
  • Уникальность уже есть: UNIQUE (user_id, team_id, new_month) — конфликт «ученик + группа + месяц».
  • Вкладка «Назначение абонементов»: store с postpay-шаблоном → 422 на lesson_package_id («назначается только в „Установка цен“…»).

2.1) UI «по месяцам»

  • Каталог пакетов в JSON (lessonPackages) содержит schedule_type и is_postpay.
  • При выборе postpay:
    • Слева (группа): span общей цены скрыт — у группы нет единой суммы (у учеников разные посещения). Вместо цены — иконка i (KidsCrmTooltip) «Сумма считается по посещениям у каждого ученика». Кнопка «Применить» остаётся: назначает шаблон postpay ученикам, не «проставляет» общую цену.
    • Справа (ученик): readonly поле числа посещений (postpay_visits), tooltip «Кол-во занятий за «{месяц}»»; в инпуте суммы — только посещения × ставка (при 0 посещений — 0), без подстановки ставки за занятие как месячного тарифа.
    • Ручная правка цены для postpay игнорируется (сервер: PostpayUsersPriceSync).
  • Стили: resources/css/style.css (.setting-prices-monthly-postpay-visits, .is-postpay-calc, .setting-prices-team-postpay-hint); без postpay select абонемента справа шире на ширину блока посещений (+ gap), чтобы строка не дёргалась; логика — resources/js/settings-prices.js (Vite).

2.2) Формула суммы

users_prices.price_cents = число актуальных статусов с consumes_lesson = true за месяц в этой группе × текущая цена шаблона (lesson_packages.price_cents). Канон денег — money (в UI — рубли).
Актуальный статус = последний event по ключу занятия (как в отчётах журнала).
При 0 посещений — 0 ₽ (кнопка оплаты недоступна, т.к. сумма ≤ 0).
Смена цены шаблона пересчитывает неоплаченные postpay-строки; оплаченные (effective_is_paid) не трогаются.

3) Журнал /schedule

  • Право: schedule.view.
  • Если у ученика на месяц есть postpay в users_prices (и месяц не оплачен) — пустые ячейки кликабельны (data-postpay="1").
  • Создание: POST /schedule/update с create_postpay=1, team_id, occurrence_date, lesson_occurrence_status_id → UTSS без ULP (user_lesson_package_id = null, is_trial_lesson = false) + статус + пересчёт users_prices.price_cents. AJAX → result.created = true + точечный DOM без reload (см. schedule-journal §6.3).
  • Списание остатка ULP для таких записей не выполняется (UserLessonOccurrenceStatusService: null-ULP non-trial).
  • Несколько групп с postpay на месяц: в модалке блок «Группа для отметки» (readonly при одной / select при нескольких); cell-context отдаёт postpay_teams, postpay_team_id.
  • Повторное открытие ячейки: у postpay-занятия показываются название пакета, группа и стоимость одного занятия (price_per_lesson из шаблона); время слота в UI журнала не показывается (для postpay API отдаёт time_start/time_end = null, is_postpay=true; для остальных типов слот остаётся техническим и тоже скрыт в модалках журнала).
  • Создание отметки (create_postpay): в meta модалки — группа · пакет · N ₽ / занятие (из postpay_teams[].price_per_lesson).
  • В модалке «Статус занятия» у статусов с consumes_lesson (в postpay-контексте) — иконка i с подсказкой «Идёт в расчёт постоплаты. Влияет на сумму за месяц.»
  • Удаление: DELETE /schedule/occurrence/{utss} → пересчёт суммы; ховер «…Стоимость абонемента будет перерасчитана.»; после оплаты кнопка disabled (см. §3.1 и schedule-journal §6.3.1).

3.1) Лок после оплаты

  • Условие: users_prices.effective_is_paid (онлайн is_paid или ручная is_manual_paid).
  • Ячейки: data-postpay-locked="1", hover KidsCrmTooltip: «Изменить данные нельзя, поскольку уже была произведена оплата».
  • Кнопка «Удалить» в модалке статуса: disabled + «Нельзя удалить: абонемент за этот месяц уже оплачен.»
  • Backend: PostpayJournalService::assertOccurrenceEditable → create / смена статуса / удаление → 422.

4) Кабинет / консоль (/cabinet)

  • Блок сезонов: setPrices.cabinetSeasons.view (см. dashboard-cabinet).
  • Payload сезонов дополняется meta: is_postpay, postpay_pay_available, postpay_pay_available_from, postpay_pay_available_label (DashboardController::cabinetUserPricesPayload + sync суммы).
  • Сумма видна в течение месяца.
  • Кнопка «Оплатить» enabled с 1-го числа следующего месяца (Europe/Moscow); до этого — disabled + tooltip «Оплата будет доступна с …».
  • Серверный guard (тот же порог): UserPriceMonthlyFeePaymentResolver — до даты → 422 с тем же текстом; уже оплачено → 422; сумма ≤ 0 → 422.
