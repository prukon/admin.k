Консоль ученика (/cabinet)

Файл: /docs/documentation/dashboard-cabinet.html · маршрут: dashboard · view: resources/views/dashboard.blade.php
Кратко. Страница «Консоль» — личный кабинет ученика (или семейный просмотр данных ребёнка): профиль, календарь посещений, блоки оплат (доп. платежи, назначенные абонементы, сезоны месячных начислений). Шапка сезона считается от текущего учебного года (сентябрь–август) вниз до 2021–2022 — §6.1, не хардкод «2025 - 2026». Доступ к странице — dashboard.view; видимость отдельных блоков оплат — отдельные permissions (§2). Для роли с правом users.view (админ CRM) доступны селекты «Группа» / «ФИО» и AJAX-подгрузка данных другого ученика. При 2+ группах у активного ученика в пользовательском режиме селект «Выбор группы» показывается, если есть setPrices.cabinetSeasons.view или setPrices.cabinetPackages.postpay.view или есть видимые назначенные абонементы (права setPrices.cabinetPackages.fixed/flexible/single.view). Фильтрация на клиенте: сезоны по users_prices.team_id, абонементы по user_lesson_packages.team_id (без team_id при селекте скрываются). Сайдбар layout admin2 при смене пункта меню не сдвигает колонку (gutter / overflow / локальный FA) — admin-layout-sidebar. Отдельно (сайдбар, шапка /cabinet, учётная запись): при account.user.team.update — добавление группы (§7.1). В той же шапке admin2 (перед «Выйти») — колокольчик in-app уведомлений при inAppNotifications.view; это не блок оплат консоли — in-app-notifications. Анонс фильтра абонементов и team_id из журнала — /doc. Учебные годы на консоли — /doc#cabinet-season-years-index. Оверлей статуса Reverb, список «Онлайн» по партнёрам и «Пульт» — часть системных мониторов: скрытое settings.systemMonitors.view (superadmin через Gate::before), переключатель в шапке слева от колокольчика, персональный флаг users.system_monitors — §8, анонс переключателя /doc, анонс списка оверлей «Онлайн», анонс пульта оверлей «Пульт», ховер 500 / ViewException / ring /doc#ops-errors-detail-index. JSON-оверлея на /cabinet нет.

2.2) Назначенные абонементы на консоли

Карточки ULP фильтруются по правам типа: setPrices.cabinetPackages.fixed.view, .flexible.view, .single.view. setPrices.packageAssignments.view на консоль не влияет. Базовые роли новых партнёров эти права не получают — выдаются вручную. Без права типа записи в БД есть, а карточки на /cabinet нет. Права проверяются у залогиненного (superadmin видит все типы через Gate::before). POST /payment этими правами не закрывается — кнопка «Оплатить» требует paying.classes. Анонс: /doc. См. set-prices-cabinet-packages, lesson-packages §assignments-tab.
  • Контроллер: DashboardController::index — выборка UserLessonPackage с fee_amount_cents > 0, eager lessonPackage:id,name,schedule_type; для view выставляется атрибут fee_amount в рублях (Money::fromCents).
  • Период под названием: для fixed / flexible — диапазон starts_at — ends_at в формате D.MM.YYYY; для разового занятия (schedule_type = no_schedule) — только дата начала, translatedFormat('j F Y') (пример: «11 августа 2026»). Если starts_at ещё нет — строка периода не выводится. Админка назначений этот формат не использует.
  • Кнопка «Оплатить» / «Оплачено» — по effective_is_paid (как в админке назначений).
  • Сумма на экране — из атрибута fee_amount (рубли); источник истины в БД — fee_amount_cents. При переходе на POST /payment resolver читает копейки (UserLessonPackageFeePaymentResolver), POST outSum не используется.
  • Блок при 2+ группах стоит под селектом «Выбор группы» и фильтруется по user_lesson_packages.team_id (data-ulp-team-id, JS filterLessonPackagesByTeam). Без team_id карточка скрывается. При одной группе селекта нет — показываются все карточки, в том числе без группы.
  • Селект показывается и без setPrices.cabinetSeasons.view, если есть видимые карточки ULP и 2+ группы.
  • При смене ученика админом через AJAX (getUserDetails) блок не перерисовывается — остаётся HTML первой загрузки (известное ограничение; сезоны и профиль обновляются через JS).

2.3) JavaScript: refreshPrice() и суммы

При пересборке сезонов функция refreshPrice() обнуляет только ячейки .seasons .border_price .price-amount (сумма отделена от символа ₽), чтобы не затирать суммы в блоках «Дополнительные платежи» и «Назначенные абонементы».

Флаг dashboardSeasonsEnabled в blade (@canany(['setPrices.cabinetSeasons.view', 'setPrices.cabinetPackages.postpay.view'])) включает createSeasons, apendPrice и пересчёт задолженности. Фильтр абонементов filterLessonPackagesByTeam вызывается до раннего выхода, если сезонов нет. Селект группы при одних карточках ULP работает и при dashboardSeasonsEnabled = false.

Размер шрифта сумм в блоках оплат и сезонах: font-size: 20px (resources/css/style.css, селекторы .custom-payments-block и .seasons). У символа ₽ — один padding-left: 0.25em (без второго зазора от соседнего flex-элемента).

2.4) Дополнительные платежи на консоли

Блок обёрнут в @can('setPrices.customPayments.view'). Базовые роли новых партнёров (user, admin, trainer) право не получают из config/role_base_permissions.php — выдаётся вручную. Без права записи в БД есть, а на /cabinet блока нет. См. setting-prices-custom-payments §1.
  • Данные: все user_custom_payment активного ученика текущего партнёра (даты в БД необязательны).
  • Карточка: сумма + ₽; подпись — поле note («Описание») в стиле .new-price-description, как подписи месяцев у сезонов. Диапазон дат на консоли не выводится.
  • Кнопка оплаты при paying.classes; уже оплаченные (effective_is_paid) — disabled «Оплачено».
  • Селект «Выбор группы» список доп. платежей не фильтрует (§5.5).

3) Контекст ученика на странице

DashboardController::index берёт ученика через FamilyStudentContextService::activeStudent(auth()->user()) — тот же механизм, что «Мои платежи» и семейный переключатель в сайдбаре.

  • Имя, дата рождения, почта, кастомные поля, расписание, users_prices, доп. платежи, назначенные абонементы — из activeStudent.
  • Аватар в шаблоне — из auth()->user() (учётка входа), не из активного ребёнка. См. parents-and-family-cabinet §5.4.
  • Группы в pivot загружаются с фильтром teams.partner_id = current_partner.

5) Селект «Выбор группы» (2+ группы)

Отдельного backend-маршрута для переключения группы на консоли нет: выбор хранится в sessionStorage браузера и применяется в JavaScript при отрисовке сезонов и карточек абонементов.

5.1) Условия показа

  • Partial: resources/views/includes/dashboard_team_switcher.blade.php (флаг $dashboardShowTeamSwitcher в dashboard.blade.php).
  • Пользователь без права users.view (@cannot('users.view')).
  • У activeStudent в pivot 2 и более групп партнёра ($curUser->teams->count() >= 2).
  • И setPrices.cabinetSeasons.view, или setPrices.cabinetPackages.postpay.view, или есть видимые назначения ULP с fee_amount_cents > 0 (права cabinetPackages.fixed/flexible/single.view).
  • При одной группе селект скрыт; жирное выделение названия группы в шапке не используется.

5.2) Размещение и подпись

  • Блок расположен сразу над назначенными абонементами и секцией сезонов (#dashboard-lesson-packages, .row.seasons), после календаря и дополнительных платежей.
  • Label селекта: «Выбор группы», элемент: #dashboard-active-team.

5.3) Поле «Группа:» в шапке профиля

  • При 2+ группах выводятся все названия через запятую (span.dashboard-group-name, атрибут data-multi-team="1" на .group-value).
  • Название группы, выбранной в селекте, выделяется жирным (<strong>) через JS (updateDashboardGroupLabel).
  • При одной группе — обычный текст без data-multi-team и без жирного.
  • Справа от .group-value — иконка карандаша (cabinet-attach-team-pencil, partial includes/cabinet_attach_team_pencil.blade.php, fa-pen) при account.user.team.update и наличии $cabinetTeamAttach; открывает ту же модалку attach (§7.1). Вне .group-value, чтобы AJAX-обновление названия не затирало иконку. Переменная $cabinetTeamAttach для контента страницы — view composer на dashboard / account.index (секция content рендерится до layout). Ховер: resources/css/style.css (opacity / цвет / scale).

5.4) Поведение при смене группы (клиент)

  1. На загрузке страницы в JS передаются все строки users_prices (userPriceAll) и список групп (dashboardTeams).
  2. Ключ sessionStorage: dashboard_active_team_id_{userId}, где userId — id активного ученика (важно при семейном переключении детей).
  3. Если в storage нет валидного id — выбирается первая группа из pivot (как дефолт на «Моя группа»).
  4. После выбора: фильтр userPrice по team_id → пересборка ячеек сезонов (apendPrice), скрытие пустых сезонов, пересчёт задолженностей; фильтр карточек абонементов (filterLessonPackagesByTeam) — только с совпадающим data-ulp-team-id, без группы скрываются, пустой блок прячется.
  5. В форме «Оплатить» за месяц в hidden team_id попадает группа отфильтрованной строки users_prices (согласовано с payments §2.1).

5.6) Связь с несколькими начислениями за один месяц

До появления селекта при 2+ группах в одной ячейке месяца могли отображаться несколько кнопок «Оплатить (Группа …)». В пользовательском режиме с активным селектом за месяц показывается одна кнопка для выбранной группы. Логика нескольких кнопок в apendPrice сохранена для админского AJAX (без селекта «Выбор группы»).

6) Сезоны и месячные оплаты

Секция .row.seasons рендерится при setPrices.cabinetSeasons.view или setPrices.cabinetPackages.postpay.view.

6.1) Какие учебные годы рисуются

Шапка сезона — не хардкод года. В dashboard.blade.php цикл range($cabinetSeasonEndYear, 2022) от конца текущего учебного года вниз до 2021–2022 (data-season="2022"). $cabinetSeasonEndYear: now()->month >= 9 ? now()->year + 1 : now()->year (учебный год сентябрь–август, TZ приложения Europe/Moscow). С 1 сентября 2026 сверху появляется «Сезон 2026 - 2027» (id="season-2027"); 31 августа 2026 верхний ещё «Сезон 2025 - 2026». Исторические сезоны не выкидываются. Ячейки месяцев по-прежнему строит JS createSeasons по data-season (сент–дек = год окончания − 1, янв–авг = год окончания). Начисление в users_prices без соответствующей шапки на странице не рисуется: apendPrice ищет подпись месяца, которую создаёт только createSeasons. Переключение группы и AJAX «ФИО» пересобирают кнопки (apendPrice), но не добавляют новые учебные годы. JS showSessons прячет сезоны с нулевой суммой, но всегда показывает первый в DOM (текущий учебный год), даже без цен. Админка «Установка цен» живёт календарным годом/месяцем — это не те же шапки; см. setting-prices-monthly-users. Семья: те же шапки, payload — activeStudent (parents-and-family-cabinet). Анонс: /doc#cabinet-season-years-index.
  • Ячейки месяцев генерируются в JS (createSeasons), цены подставляются из массива userPrice (или отфильтрованного под группу).
  • Каждая оплачиваемая ячейка содержит paymentDate, formatedPaymentDate (YYYY-MM-01), hidden team_id, outSum (на сервере для monthly_fee не источник истины).
  • Resolver оплаты: UserPriceMonthlyFeePaymentResolver — при нескольких начислениях за месяц без team_id в POST → 422 «Укажите группу…»; селект на консоли как раз передаёт нужный team_id.
  • Постоплата: месяцы с schedule_type=postpay попадают в payload только при setPrices.cabinetPackages.postpay.view (это право не то же, что lessonPackages.type.postpay в CRM). В payload — is_postpay, postpay_pay_available*. Сумма видна сразу; кнопка оплаты enabled с 1-го числа следующего месяца (МСК), до этого disabled. Ховер «Оплата будет доступна с …» — на обёртке @include('partials.ui.tooltip-hint') (#dashboard-disabled-pay-hint-tpl, kids-tooltip-hint--control), не на самой disabled-кнопке. Сервер дублирует правило в resolver. Подробно — postpay § кабинет, set-prices-cabinet-packages.
