Гость — редирект / 401. Прямой Team::create (factory/seed) чат сам не создаёт — только TeamService::store, attach ученика/тренера (ensureThreadForTeam) или backfill.

3) Ученик. Привязка к группе (TeamUserSyncService) добавляет в чат этой группы. Несколько групп — состоит во всех этих чатах. Снятие группы / удаление учебной группы ученика из чата не выгоняет. Soft-delete учебной группы чат не удаляет и никого не кикает. Пути: карточка team_ids (POST/PATCH /admin/users), журнал POST /schedule/user/{user}/sync-teams, ЛК POST /cabinet/teams/attach.
4) Тренер. Привязка к группе (TeamTrainerSyncService) добавляет в чат. Отвязка из чата не убирает. Пути: мультиселект тренеров в модалке группы и team_ids[] на /admin/trainers.

Включение добавляет только в соответствующие чаты учебных групп (ученик — текущий pivot, тренер — team_trainer, админ — все чаты школы, superadmin — все). Личка с лишним SA скрыта из inbox; прямой GET треда участнику всё равно отдаёт заголовок «Служба поддержки», не ФИО. Канонический ряд — отдельный ORDER BY id LIMIT 1 в начало списка. Поиск ?q= — только по подписи «Служба поддержки», не по ФИО/email учётки. «Все группы» и «Без группы» (none) — показывают поддержку; фильтр конкретной учебной группы — нет. 3) Ограничения: ends_at ≥ starts_at и не раньше даты последнего занятия в календаре по этому назначению (max(user_team_schedule_slots.starts_at)).
4) При сохранении обновляется user_lesson_packages.ends_at и синхронизируется ends_at у связанных строк календаря; новые занятия не создаются и не удаляются (в т.ч. для фиксированного абонемента цепочка не достраивается).
5) Это не меняет правило конфликта assign-fixed: занятость ученика по-прежнему ключуется по user_team_schedule_slots.starts_at, а не по «хвосту» ends_at строки.

Конфликт привязки фиксированного абонемента: дата = starts_at (2026‑07)

При POST …/school-schedule/assign-fixed проверка пересечения времени у ученика смотрит только на дату занятия в календаре — user_team_schedule_slots.starts_at. Поле ends_at у строки календаря (для flexible/fixed/разового часто = конец периода назначения user_lesson_packages.ends_at; у пробного ends_at = starts_at) не разворачивает занятие на последующие дни недели.
Раньше интервал starts_at…ends_at + тот же weekday давал ложный «Конфликт расписания» на даты после последнего реального занятия, пока не истёк срок абонемента (например, новый фикс с якоря 27.07 при старой записи с starts_at=20.07 и ends_at=29.07).
Календарь недели, статусы и автосписание и раньше опирались на starts_at — проверка конфликта приведена к той же модели. Время в один и тот же день по-прежнему конфликтует; разные слоты без пересечения часов в один день — нет.
Проверка кросс-слотового пересечения времени есть только у assign-fixed (цепочка). Гибкий / разовое / пробное проверяют дубликат «тот же слот + дата» (starts_at), без сравнения часов между разными слотами.
