Чат: черновик сообщения на сервере (2026‑08)

Набранный и не отправленный текст больше не живёт только в поле ввода: при переключении диалога он не «переезжает» к другому собеседнику и не теряется после F5. Это не черновик ЗП тренеров (Канзас) и не только sessionStorage. Не путать превью «Черновик:» со временем справа и с бейджем непрочитанных (анонс чата, онлайн / карточка).

1) Где хранится. Колонка participants.draft_body (nullable text, до 5000 символов) у текущего участника диалога. Собеседник в JSON списка и GET /chat/api/threads/{id} видит только свой черновик (чужой не отдаём). Пустая строка и одни пробелы после trim — стереть (NULL в БД, в JSON draft_body: '').
2) API. PATCH /chat/api/threads/{thread}/draft (chat.api.threads.draft, право messages.view, только участник). Поле body (можно опустить — стереть). AJAX → JSON 200 {ok: true, draft_body}. Нативный PATCH без X-Requested-With → 302 на /chat, запись в БД есть (не сырой JSON 200). Не участник — 403. Нет треда — 404. Длиннее 5000 или не строка — 422 errors.body («Черновик слишком длинный…» / «Черновик должен быть строкой.»), прошлый черновик не затирается. GET/POST/DELETE этого URI → 404/405, не 500 и не пустой 200. Сохранение черновика не шлёт inbox.bump собеседнику.
3) Список слева. Если свой draft_body непустой — превью Черновик: … вместо последнего сообщения (.chat-li-preview.is-draft, цвет #f3a12b, курсив). Время справа остаётся last_message_time (в JSON last_message тоже остаётся). Пробельный черновик превью не рисует. HTML в тексте экранируется. Поиск по списку ищет и по тексту черновика.
4) Клиент. Набор — debounce 500 мс, превью в списке сразу. Уход в другой диалог сохраняет сразу (persistLeavingDraft) и подставляет черновик открытого в #msgInput (после setComposerEnabled(true)), затем фокус. Повторный клик по тому же диалогу PATCH не шлёт. Опрос inbox раз в 1 с не затирает поле и не откатывает локальный набор более старым серверным значением. Успешная отправка обнуляет черновик отправителя; неуспешная — текст и превью «Черновик:» остаются. Входящее сообщение собеседника мой черновик не стирает. InboxBump после send несёт draft_body: '' только отправителю (у собеседника ключа нет, чтобы не затереть его кэш).

Подробно — chat §черновик, чат — анонс чата. Конфликт привязки фиксированного абонемента: дата = starts_at (2026‑07)

При POST …/school-schedule/assign-fixed проверка пересечения времени у ученика смотрит только на дату занятия в календаре — user_team_schedule_slots.starts_at.
