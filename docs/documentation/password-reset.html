Сброс пароля: гонка POST /password/email не даёт HTTP 500

Файл: /docs/documentation/password-reset.html · анонс: /doc
Кратко. Форма запроса ссылки /password/reset (с /login — «Забыл пароль.») шлёт native POST /password/email (password.email). Guest middleware нет (гость не уходит на логин). Laravel DatabaseTokenRepository делает DELETE+INSERT в password_reset_tokens (PK = email) без транзакции. Два параллельных клика оба проходят throttle 60 с и один ловит MySQL 1062 (UniqueConstraintViolationException). С 2026‑09 контроллер отвечает как на успех (письмо уже ушло у победителя), не 500 и не строка «500» пульта. Кнопка после submit становится disabled в setTimeout(0). Это не unique на users.email, не журнал my_logs и не форма нового пароля по токену. Вход / сессия 30 дней — session-lifetime.

1) Как открыть

  • С /login: ссылка «Забыл пароль.» (route('password.request') в resources/views/auth/login.blade.php).
  • Прямой GET /password/reset — 200 HTML, не 302 на /login, не 401, не 403.
  • У ForgotPasswordController нет middleware('guest') (у LoginController есть). Залогиненный, в том числе без groups.view, форму видит и POST может отправить.

2) Форма запроса ссылки

  • Blade: resources/views/auth/passwords/email.blade.php, layout layouts.app (гость), noindex, nofollow.
  • Native POST на route('password.email'), без AJAX / fetch / $.ajax / preventDefault на первом submit.
  • Поля: #email / name="email". Ошибки Laravel под полем (@error('email'), is-invalid).
  • Успех: flash status в alert-success («Мы отправили вам ссылку для сброса пароля на ваш email.»), не под полем.
  • Кнопка #forgot-password-submit. После первого submit форма ставит data-submitting="1" и disabled на кнопку; повторный submit — event.preventDefault(). disabled ставится в setTimeout(0), иначе браузер отменяет native POST. На первом GET кнопка не disabled и форма без data-submitting. Не закрывает уже ушедшие параллельные POST — это закрывает сервер (§3).

3) HTTP POST /password/email

Валидация — SendPasswordResetLinkRequest (не trait validateEmail): email required|email|max:255. Тексты под полем: «Укажите email.», «Введите корректный email.», правило max:255 (слишком длинное значение — 422 под email; текст email.max или email.email, если формат отсекает раньше).

Кто / методОтвет
Гость GET /password/reset 200 HTML, форма #forgot-password-form. JSON Accept тоже HTML-форма. Не 302 на /login, не 401, не 403 (guest middleware нет, в отличие от /login).
Залогиненный GET /password/reset 200 HTML (guest middleware на этом контроллере нет, в отличие от /login), не 500.
Гость POST пустой / некорректный email HTML: 302 + session errors.email («Укажите email.» / «Введите корректный email.»). JSON + X-Requested-With: 422 errors.email.0.
Гость POST неизвестный email HTML: 302, errors.email «Мы не нашли пользователя с таким email адресом.» JSON wantsJson: 422 тот же текст.
Гость POST успех (native) 302 назад на форму, flash status, письмо ResetPasswordNotification. Не пустой 200.
Гость POST успех (JSON) 200 {message} (Laravel UI SendsPasswordResetEmails::sendResetLinkResponse), не 204 входа.
Гость POST повтор в пределах throttle 60 с Не 500. HTML: 302, errors.email «Пожалуйста, подождите перед повторной попыткой.» Второе письмо не уходит.
Гость POST гонка 1062 (UniqueConstraintViolationException на PK email) Как успех: native 302 + status; JSON 200 + message (без errors.email, не текст throttle). Не 500, не throttle, OpsMonitor errors.count не растёт. Письмо этим запросом не шлётся (бросает до sendPasswordResetNotification).
GET/PATCH/PUT/DELETE /password/email 405 (или отказ), не 500, не пустой 200.
  • Контроллер: ForgotPasswordController::sendResetLinkEmail ловит только UniqueConstraintViolationException и ставит Password::RESET_LINK_SENT.
  • Throttle 60 с — config/auth.php passwords.users.throttle. Гонку двух первых запросов он не закрывает (оба не видят свежий токен).
  • CRM-права на запрос ссылки не нужны (admin без groups.view, trainer, ученик). Залогиненный без права кабинета — не 403 на GET/POST.
  • JSON неизвестный email / throttle — строго 422 errors.email (Laravel UI wantsJson), не 302.

4) Не путать с формой нового пароля

  • Эта страница — только запрос письма. Ссылка в письме ведёт на GET /password/reset/{token} (password.reset), сохранение — POST /password/reset (password.update, ResetPasswordController).
  • После успешного сброса по токену sendResetResponse редиректит на /login со flash status («Ваш пароль был сброшен!»), не на /cabinet (поле $redirectTo в контроллере этим методом перекрыто).
  • Гонка 1062 и disabled кнопки относятся только к POST /password/email.
