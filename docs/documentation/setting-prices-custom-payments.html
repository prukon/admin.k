Установка цен → Дополнительные платежи

Файл: /docs/documentation/setting-prices-custom-payments.html. Страница CRM: /admin/setting-prices/custom-payments (вкладка custom_payments в admin/SettingPrices/index).
Группа платежа: с 2026‑06 у каждой записи user_custom_payment при создании в админке обязателен team_id. Группа определяет юр. лицо и маршрут выплаты T‑Bank при оплате (PayableTeamResolver → payables.meta.team_id). Подробно — payments §2.3.

1) Права доступа

PermissionНазначение
setPrices.viewРодительский middleware раздела «Установка цен» (обязателен для всех URL вкладки)
setPrices.customPayments.viewВкладка «Дополнительные платежи»; GET page/data/users-search/teams-for-user; POST store; блок доп. платежей на консоли (/cabinet)
setPrices.manualPaid.managePUT update, DELETE destroy, POST …/{id}/manual-paid; кнопка «Редактировать» в таблице (флаг window.__customPaymentsCanManualPaid)
setPrices.cabinetSeasons.viewНе относится к доп. платежам — только сезоны на консоли. См. dashboard-cabinet §2.1
Право setPrices.customPayments.view не входит в базовый набор ролей user, admin и trainer (config/role_base_permissions.php) — для новых партнёров выдаётся вручную в матрице прав. Существующих партнёров конфиг не меняет. Без права блок доп. платежей на /cabinet не показывается, даже если записи в БД есть.

Гость — 302/401/403. Без setPrices.view — 403 на раздел. Без setPrices.customPayments.view — 403 на page/data/store/search. Без setPrices.manualPaid.manage — 403 на update/delete/manual-paid. Успешные ответы — 200 / 422 / 404 (не 500, не пустой 200).

3) UI админки

3.1) Таблица

  • Таблица #custom-payments-table (KidsCrmDataTable): колонки ID, Ученик, Группа, Сумма, Описание (note), Статус, Действия.
  • Колонки «Период» в UI нет (даты в БД по-прежнему nullable; в JSON data поле period может быть «—»).
  • В «Действия» при праве manualPaid.manage — только кнопка «Редактировать» (отдельных кнопок «Оплачено»/«Не оплачено» в таблице нет).
  • JS: resources/js/setting-prices-custom-payments.js (на стенде без vite build может отдаваться из public/js/setting-prices-custom-payments.js).

3.2) Модалка создания

  • Поля: ученик (Select2 AJAX), группа (Select2 AJAX после выбора ученика), сумма (step=1, без копеек), «Описание (отображается у ученика)» (note).
  • Полей «Дата начала» / «Дата окончания» нет.
  • Если у ученика ровно одна группа — она подставляется автоматически после teams-for-user.
  • Успех: showSuccessModal('Дополнительный платеж', '…успешно создан.') (не toast).
  • Ошибки 422 — под полями (.custom-payment-field-error).

3.3) Модалка редактирования

  • Поля: сумма (readonly/disabled, если уже оплачен), статус оплаты, описание (note), при смене статуса — обязательное «Комментарий к изменению статуса оплаты» (status_comment, min 3).
  • Ученика и группу менять нельзя.
  • Кнопка «Удалить» (слева в footer) видна только если effective_is_paid === false; подтверждение через showConfirmDeleteModal.
  • Ошибки 422 — под полями (.custom-payment-edit-field-error).

3.4) Валидация update

  • UserCustomPaymentUpdateRequest:
    • если платёж не оплачен — amount required, numeric, min 0.01;
    • если оплачен — amount prohibited (сумму менять нельзя);
    • is_paid required boolean;
    • status_comment required, если новый статус ≠ текущему effective_is_paid;
    • note nullable, max 255.
  • При смене статуса пишутся is_manual_paid, manual_paid_by, manual_paid_at, manual_paid_note.

4) Валидация store

  • UserCustomPaymentStoreRequest: user_id, team_id required; ученик — системная роль user; ученик состоит в группе; amount required; note nullable; date_start/date_end nullable (из UI не приходят).

5) База данных

  • Таблица user_custom_payment: partner_id, user_id, team_id, amount, note, date_start/date_end (nullable), is_paid, is_manual_paid, manual_paid_*.
  • Accessor effective_is_paid: если is_manual_paid !== null — он, иначе is_paid.
  • Миграции team_id / backfill — как раньше (2026_06_29_150000, 2026_06_29_160000).

6) Консоль ученика (/cabinet)

  • Блок виден при @can('setPrices.customPayments.view') и наличии строк у activeStudent.
  • На карточке: сумма + ₽ (один отступ слева у символа), подпись — note в стиле .new-price-description (как «Октябрь 2025» у сезонов). Даты «от–до» на консоли не показываются.
  • Оплата: payment_kind=custom_payment, custom_payment_id. См. dashboard-cabinet §2.4, payments §3.3.

7) Связь с оплатой

При Init (custom_payment_fee) PayableTeamResolver читает user_custom_payment.team_id. Без группы на записи — 422 при старте оплаты. Источник суммы — user_custom_payment.amount (не POST outSum). Webhook выставляет is_paid=1.

Селект «Выбор группы» на консоли не фильтрует доп. платежи — группа зафиксирована при создании. См. dashboard-cabinet §5.
