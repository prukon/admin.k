Кабинет: стабильный сайдбар

Файл: /docs/documentation/admin-layout-sidebar.html · layout: resources/views/layouts/admin2.blade.php · анонс: /doc
Кратко. Кабинет — обычный MPA: при клике в левом меню страница перезагружается целиком. Сайдбар прыгал по двум причинам: у коротких и длинных страниц то появляется, то пропадает вертикальный скролл окна (центрированная колонка .wrapper { max-width: 1280px } в style.css + .layout-fixed .main-sidebar { left: auto }), и AdminLTE на window.load ставит overflow-y: auto на .sidebar (до этого overflow-y: initial, скролл none, по hover — thin). Отдельно иконки пунктов приезжали с CDN Kit после текста — меню дёргалось второй раз.

1) Где действует и где нет

  • Действует на всех страницах layout admin2: консоль /cabinet, списки с тулбаром (/admin/users и др.), журнал, настройки. Правила в <head> layout, поэтому gutter одинаковый и на странице без admin-list-toolbar.css, и на странице с тулбаром.
  • Не действует на лендинге (layouts/landingPage.blade.php): нет html { scrollbar-gutter: stable }, нет слота .nav-icon, нет селекторов .layout-fixed .main-sidebar.
  • Лендинг использует тот же partial иконок includes.fontawesome (локальный FA 6, без Kit). Это не «admin-gutter на публичной витрине».
  • Нового permission нет. Страницы кабинета по-прежнему требуют свои права (dashboard.view, users.view, …). Эту страницу документации видит роль с documentations.view (/doc, /docs/documentation/admin-layout-sidebar).

2) Скролл и колонка

  • html { scrollbar-gutter: stable; } в <head> layout admin2 (с первого кадра, не ждём Vite) и дубль в resources/css/style.css. Браузеры без scrollbar-gutter — html { overflow-y: scroll; }.
  • У .layout-fixed .main-sidebar .sidebar сразу overflow-y: auto, scrollbar-gutter: stable и постоянный scrollbar-width: thin (webkit width/height: 0.5rem), без смены ширины по hover.
  • Плагин OverlayScrollbars не подключаем в layout (ни CSS, ни JS). Файлы могут лежать в public/plugins/overlayScrollbars/ — AdminLTE их не грузит. Иначе плагин оборачивает .sidebar после window.load и сдвигает пункты.
  • Тот же scrollbar-gutter убран из admin-list-toolbar.css — он был только на страницах с тулбаром, поэтому при переходе «список ↔ консоль» колонка прыгала.

3) Иконки меню — локальный Font Awesome 6

Раньше иконки сайдбара рисовал Font Awesome Kit (public/js/fontawesome/fontawesome.js → CDN ka-f.fontawesome.com, версия 6.5.1). Текст пунктов был сразу, глифы приезжали после запроса на CDN. Старый локальный FA5 в plugins/fontawesome-free классы fa-solid не понимал, woff2 не было.

  • На сервере Font Awesome Free 6.5.1: public/plugins/fontawesome-free/css/all.min.css + webfonts/fa-solid-900.woff2 (и regular/brands). Подключение — partial includes/fontawesome.blade.php (кабинет admin2 и лендинг). Файл Kit удалён, в layout нет <script src="…/fontawesome.js">.
  • В partial: preload solid woff2 до CSS, плюс v4-shims / v4-font-face / v5-font-face (старые fas и font-family AdminLTE). В partial нет <script>. URL CSS и woff2 с ?v=filemtime: путь тот же, что у старого FA5, без версии браузер держит кэш и рисует квадратики вместо иконок (пока не Ctrl+F5).
  • Слот .nav-sidebar > .nav-item .nav-icon: display: inline-block; width/min-width: 1.6rem; text-align: center; flex-shrink: 0 с первого кадра. У AdminLTE ширина уже была, но на inline-<i> она не действует, пока FA не поставит inline-block.

5) Vite и ассеты

Стабильность сайдбара не зависит от npm run build: gutter и слот иконки живут в inline <style> layout, шрифты — в public/plugins/fontawesome-free. Дубль в style.css нужен, когда Vite CSS уже загружен; до него хватает правил из <head>.

6) Чего это не убирает

Полной «заморозки» DOM сайдбара как в SPA нет: HTML меню каждый раз новый. Остаётся лёгкая вспышка активной ссылки и перерисовка страницы. Горизонтальный прыжок колонки, подпрыгивание пунктов после load и позднее появление иконок — цель этих правил.

7) Ширина кабинета (на всю ширину экрана)

По умолчанию колонка кабинета ограничена .wrapper { max-width: 1280px }. В шапке справа (после колокольчика, перед «Выйти») есть кнопка, которая снимает ограничение на ширину окна. Настройка хранится у конкретного пользователя в users.layout_wide, не в браузере и не у партнёра. На мобильном кнопка скрыта (d-none d-md-flex). Лендинг не затрагивается.
  • Класс layout-wide ставится на body сразу из Blade (без вспышки 1280px). CSS дублируется в <head> layout и в resources/css/style.css, чтобы не зависеть от npm run build.
  • Кнопка: partial includes/layout_wide_toggle.blade.php. Иконки fa-expand-alt / fa-compress-alt.
  • Сохранение: POST /cabinet/layout-wide (cabinet.layout-wide.update), auth + 2fa, без отдельного permission. Request UpdateLayoutWideRequest: поле layout_wide, ошибки JSON под ключом errors.layout_wide и выводятся под кнопкой.
  • После переключения фронт шлёт resize и вызывает DataTable.columns.adjust(), чтобы таблицы не остались узкими.
  • Нативный POST без AJAX — redirect назад + flash status, не сырой JSON 200.

8) Связанные разделы

  • Консоль (/cabinet) — содержимое правой колонки, не CSS сайдбара.
  • Переиспользование UI — тулбар списков без window-gutter.
  • Родители и семейный кабинет — пункты сайдбара (переключатель ребёнка, «Группа»).
