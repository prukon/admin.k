Сессия 30 дней, «Запомнить меня», страница 403

Файл: /docs/documentation/session-lifetime.html · анонс: /doc
Кратко. Дефолт config/session.php — SESSION_LIFETIME=43200 (30 суток idle). Драйвер по-прежнему file, redis/database этот инкремент не вводит. Фактический срок на инстансе = env('SESSION_LIFETIME'): если в .env осталось старое значение 120 минут, пользователи живут два часа, даже при дефолте 43200 в config. На /login галка «Запомнить меня» включена с первого показа. HTML 403 для гостя — layouts.app, не кабинетный admin2 (иначе auth()->user()->role на null превращал 403 в 500 и писал ErrorException в строку «500» пульта).

1) Срок сессии

  • config/session.php: lifetime = (int) env('SESSION_LIFETIME', 43200).
  • 43200 минут = 30 суток бездействия. Закрытие браузера сессию не убивает (expire_on_close = false).
  • Чтобы на сайте было 30 дней, в .env (и на тесте — в .env.testing) должно быть SESSION_LIFETIME=43200. Переменная окружения побеждает дефолт config.
  • PHPUnit: phpunit.xml SESSION_LIFETIME 43200 с force="true" (иначе .env.testing перебивает). Feature-тесты срока проверяют исходник config, не runtime-значение без force.
  • Пока открыта любая страница кабинета (layouts.admin2), POST /presence/ping (presence.ping) раз в минуту (includes/in_app_notifications/echo.blade.php, setInterval(ping, 60000), credentials: 'same-origin') сдвигает mtime файла сессии. Это тот же ping, что онлайн в чате (chat §2.1), не отдельный keepalive.
  • Драйвер SESSION_DRIVER=file, каталог storage/framework/sessions. Сборщик лотереи [2, 100] без изменений.

2) «Запомнить меня»

  • Форма resources/views/auth/login.blade.php — native POST на route('login'), без AJAX / preventDefault / дубликата JS.
  • Чекбокс #remember / name="remember". Порядок полей: email → password → remember.
  • Первый GET /login — атрибут checked (нет old()).
  • После редиректа с withInput() (session()->hasOldInput()): галка как в POST. Сняли и ошиблись в пароле — остаётся снятой. old('remember') без hasOldInput() снова включил бы галку.
  • После logout повторный GET снова с checked (новой сессии без old input).
  • Сервер: AuthenticatesUsers / $request->boolean('remember'). Поля нет — remember-cookie не ставится. Поле есть — cookie recaller ~400 дней (SessionGuard rememberDuration 576000 минут). Это не idle-сессия.
  • CRM-права на вход не нужны: admin без groups.view, trainer и ученик входят так же.

3) HTTP /login и /logout

Капча на живой форме в PHPUnit не участвует (CSRF в тестах снят). Ошибки полей — не Form Request: пустые поля валидирует AuthenticatesUsers, неверный email/пароль — LoginController::sendFailedLoginResponse.

Кто / методОтвет
Гость GET /login 200 HTML, форма, #remember checked. JSON Accept тоже HTML-форма, не пустой 200 без разметки.
Залогиненный GET/POST /login 302 /cabinet (guest middleware), не 500 и не пустой 200.
Гость POST пустые email/password HTML: 302 + session errors.email / errors.password («Поле электронная почта обязательно…», «Поле пароль обязательно…»). JSON + X-Requested-With: 422 errors.email.0 / errors.password.0.
Гость POST неизвестный email 302 (в т.ч. AJAX: контроллер делает back()->withErrors, не ValidationException). errors.email «Такой email не найден.» Пароль не трогает.
Гость POST неверный пароль 302, errors.password «Неправильный пароль.» Email не трогает. Текст под полем в HTML (is-invalid).
Гость POST успех (native) 302 /cabinet, сессия создана. Не пустой 200.
Гость POST успех (JSON, wantsJson) 204 пустое тело (Laravel AuthenticatesUsers::sendLoginResponse), не 200.
PATCH/PUT/DELETE /login 405 (или отказ), не 500, не пустой 200.
POST /logout Залогиненный HTML → redirect /. JSON → 204 или redirect. Гость — отказ, не пустой 200.

4) Страница 403 и /broadcasting/auth

  • resources/views/errors/403.blade.php: @extends(auth()->check() ? 'layouts.admin2' : 'layouts.app').
  • Гость: лейаут логина, кнопка «Войти» на route('login'), noindex, nofollow через @push('meta'), без main-sidebar и без #js-ops-monitors.
  • Залогиненный: кабинетный лейаут, кнопка «На главную» на /.
  • Сайдбар admin2: auth()->user()?->role?->label (не optional(auth()->user()->role) — тот всё равно читает ->role у null). Имя/почта тоже nullsafe. Подробно про сайдбар — admin-layout-sidebar.
  • Broadcast::routes() в BroadcastServiceProvider — GET+POST /broadcasting/auth, web-стек, без middleware auth. Гость получает HTTP 403, не 401 и не редирект на /login.
  • Echo (includes/in_app_notifications/echo.blade.php) бьёт authEndpoint: '/broadcasting/auth' без Accept: application/json — Laravel рисует HTML 403. Типичный каскад до фикса: протухшая сессия → этот POST → AccessDeniedHttpException 403 → рендер HTML 403 через admin2 → ErrorException «Attempt to read property "role" on null». HTTP оставался 403, но Handler::renderHttpException вызывал report() на ViewException — пульт видел 500. Сам HTTP 403 по-прежнему не пишется в строку 500 (Handler режет 4xx). После фикса гостевой 403 errors.count не увеличивает. Пульт: ховер 500, dashboard-cabinet §8.
  • Свой канал private-inbox.{id} — 200, право messages.view не нужно. Чужой inbox — 403 (залогиненному HTML с admin2). JSON с Accept: application/json — 403 JSON message, не HTML 500.
  • PATCH/PUT/DELETE на /broadcasting/auth — 405, не 500.
