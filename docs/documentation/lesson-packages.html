Абонементы (lesson packages): назначение ученику и даты периода

Запись user_lesson_packages — полноценная бизнес-сущность сразу после создания на странице «Назначение абонементов». Поля starts_at и ends_at могут быть NULL до первой привязки к календарю расписания школы.

Шаблоны абонементов (UI): два экрана с общим partial и общими CRUD API — «Расписание школы» → /admin/lesson-packages и дубль в «Справочниках» → /admin/directories/lesson-packages (§packages-tab, §directories-packages-tab).

История назначений (2026‑08): на вкладке «Назначение абонементов» — кнопка «История» (категория аудита user_lesson_package, отдельно от шаблонов lesson_package и календаря schedule). Подробно — §assignments-history.

Тип шаблона postpay (постоплата)

Отдельный schedule_type для оплаты по факту посещений за календарный месяц. Биллинг — только через users_prices (без строки в user_lesson_packages). Option/фильтр «Постоплата» в UI шаблонов — только при праве lessonPackages.type.postpay (lesson-packages-type-postpay). В select назначений ULP тип не предлагается без этого права; store назначения с postpay-пакетом всегда → 422 (доменный запрет). Полное описание — postpay.

Поле billing_month (месячные назначения из установки цен)

Миграция 2026_08_01_030000_add_billing_month_to_user_lesson_packages_table.php. Колонка user_lesson_packages.billing_month — date, nullable, смысл как у users_prices.new_month: хранить 1-е число месяца (YYYY-MM-01). Неуникальный индекс (user_id, team_id, billing_month). С 2026‑08 при сохранении assignable-пакета в установке цен (UsersPriceLessonPackageSync) создаётся ULP с заполненным billing_month, ends_at = последний день месяца; для flexible сразу starts_at = 1-е число месяца (занятия ставят по клику в журнале — §7.3); для fixed / no_schedule — starts_at = NULL (в журнале «+» у fixed доступен, пока нет старта/UTSS), и FK users_prices.user_lesson_package_id (миграция 2026_08_05_190000_add_user_lesson_package_id_to_users_prices_table.php). Модалка раскладки журнала (fixed): для месячных ULP дата начала обязательна и пустая по умолчанию (только внутри billing_month), окончание — readonly; HTML5 min/max/required не используются — ошибки Laravel под полями. Классика без billing_month: при первой привязке к календарю ends_at = start + duration_days шаблона. Ручные назначения без месяца по-прежнему могут иметь billing_month = NULL. Backfill старых users_prices не делается. Не путать с постоплатой: тип postpay не пишет в ULP и не использует billing_month — см. postpay. См. также payments § billing_month, setting-prices-monthly-users § ULP sync, schedule-journal §7.

«Разложено» vs «placeable» в журнале

  • UserLessonPackage::isLaidOutInSchedule() — уже разложено, если есть starts_at, или есть UTSS, или (для не-месячных) заполнен один ends_at.
  • Исключение — месячный flexible (billing_month + тип flexible): полный период при sync не означает раскладку; laid out только при наличии UTSS.
  • Для месячных fixed (billing_month): один заранее выставленный ends_at без starts_at и без UTSS — ещё не раскладка; кнопка «+» в журнале доступна.
  • isJournalPlaceable() = не laid out и lessons_total > 0 (раскладка «+» из журнала — только schedule_type = fixed; гибкий — отдельная модалка по клику на ячейку).

Правило периода

При первой привязке назначения к календарю / журналу (UserLessonPackageCalendarPeriodService::applyFirstCalendarAnchor):

Тип назначенияstarts_atends_at
Месячный flexible из установки цен Сразу при sync = 1-е число billing_month Сразу при sync = последний день месяца; duration_days не используется
Месячный fixed / no_schedule из установки цен Дата якоря раскладки (обязательна, внутри месяца начисления) Уже задан при sync = последний день billing_month; duration_days шаблона не используется
Классика (billing_month = NULL) Дата якоря привязки starts_at + duration_days шаблона (lesson_packages.duration_days)

Если период уже полностью задан (обе даты не NULL), повторно через этот механизм он не перезаписывается. Для фиксированного абонемента повторная привязка того же назначения блокируется, если назначение уже «разложено» (isLaidOutInSchedule) или есть строки в user_team_schedule_slots.

После первой привязки дату окончания можно скорректировать вручную — см. § ручная смена ends_at (редактирование в UI назначений доступно, когда заполнены обе даты периода).

Ручная смена даты окончания (ends_at)

UI только на вкладке «Назначение абонементов» (/admin/lesson-packages/assignments), модалка #ulpAssignmentEditModal («Изменение абонемента»). На календаре школы отдельного редактора периода нет.

Поведение UI

  • Период ещё не задан (starts_at/ends_at = NULL) — одно поле «Период» со значением «не задан» (readonly). Флаг JSON period_editable = false.
  • Период задан — два поля: Дата начала (#ulp-modal-period-start, только просмотр) и Дата окончания (#ulp-modal-period-end, редактируемая). period_editable = true.
  • Ошибки валидации выводятся под полем окончания (#ulp-modal-period-end-err).

API и валидация

  • Endpoint: PUT /admin/lesson-packages/assignments/{id} (UpdateUserLessonPackageAssignmentRequest), права lessonPackages.view + setPrices.packageAssignments.view.
  • Если период задан — поле ends_at (Y-m-d) обязательно в теле запроса вместе с fee_amount.
  • Если период не задан — ends_at prohibited (попытка передать дату → 422).
  • ends_at ≥ starts_at.
  • ends_at не раньше даты последнего занятия в календаре по назначению (max(user_team_schedule_slots.starts_at) где user_lesson_package_id = id назначения). Равенство дате последнего занятия разрешено.
  • AJAX (X-Requested-With / Accept: application/json): успех → 200 { success, assignment }; ошибка → 422 + errors.ends_at.
  • Non-AJAX: успех → 302 на вкладку назначений + flash «Назначение абонемента обновлено»; валидация → 302 back + session errors (не пустой 200).

Побочные эффекты при сохранении

  • Обновляется user_lesson_packages.ends_at; starts_at не меняется.
  • У всех связанных строк user_team_schedule_slots с этим user_lesson_package_id поле ends_at синхронизируется с новым концом периода (как при создании flexible/fixed/разового — там utss.ends_at = конец периода назначения; у пробного без ULP это не затрагивается).
  • Не создаются и не удаляются занятия календаря: удлинение периода для фикса не достраивает цепочку; укорачивание (в пределах «не раньше последнего занятия») не снимает уже стоящие слоты.
  • lessons_remaining / lessons_total не меняются.
  • Правило конфликта assign-fixed не меняется: занятость ученика по-прежнему по utss.starts_at, а не по «хвосту» utss.ends_at (см. § конфликт).

Сервис: UserLessonPackageCalendarPeriodService::updateEndsAt. Request/контроллер: UpdateUserLessonPackageAssignmentRequest, LessonPackageController::updateAssignment.

Тесты: LessonPackageAssignmentEndsAtAccessFeatureTest, LessonPackageAssignmentEndsAtNonAjaxSafetyNetFeatureTest, LessonPackageAssignmentEndsAtAjaxContractFeatureTest, LessonPackageAssignmentEndsAtWorkflowFeatureTest, BladeInlineJsSyntaxTest::test_lesson_package_assignment_ends_at_modal_inline_script_is_valid_javascript (также частично в LessonPackageAssignmentsTabFeatureTest).

Гибкое расписание

Эндпоинт привязки одного занятия (assign-flexible) выставляет период при первом успешном сохранении привязки, если даты ещё были NULL. Одна успешная операция добавляет одну строку в user_team_schedule_slots; при достижении лимита по числу строк (равному lessons_total) следующая привязка возвращает ошибку валидации.

UI календаря школы: привязка выполняется inline в модалке слота (без отдельной модалки «Гибкий абонемент»). Список подходящих назначений на дату — в GET …/slot-user-bind-actions → flexible.existing_assignments; подпись назначения — "название" (остаток N) (см. school-schedule-calendar § подписи); одно назначение — две строки на кнопке и один клик, несколько — select в #schoolCalSlotFlexFormWrap. Подробности — в разделе «Расписание школы» (§ «Гибкие абонементы в модалке слота»).

UI журнала /schedule: месячный flexible из установки цен (billing_month) ставится по клику на ячейку — schedule-journal §7.3 (place-flexible-abonement: статус в модалке, без reload страницы). Классика без billing_month из журнала не предлагается.

Фиксированное расписание

В модалке календаря выбирается уже существующее назначение (user_lesson_package_id) без периода; затем по якорной дате и шаблону (patterns[]: день недели и интервал времени) строится цепочка занятий и создаются строки user_team_schedule_slots. Период назначения задаётся в той же транзакции перед построением цепочки (UserLessonPackageCalendarPeriodService::applyFirstCalendarAnchor).

Длина цепочки ограничена доступным «слотом» в календаре: берётся lessons_total − уже существующее число строк по этому назначению. Если за период абонемента не удаётся разместить все вхождения шаблона или есть конфликты — привязка отклоняется с сообщением об ошибке (TeamScheduleCalendarService: проверка шаблона, построение цепочки, пересечения с другими занятиями ученика).

Конфликт по времени (assign-fixed)

Перед созданием строк вызывается TeamScheduleCalendarService::assertFixedChainHasNoTimeOverlapWithExistingUserLessons.

  • Для каждой даты цепочки ищутся строки user_team_schedule_slots ученика с starts_at = эта дата (дата занятия в календаре — так же, как в недельном API, статусах и автосписании).
  • Если время слота кандидата пересекается со временем слота найденной записи — ошибка «Конфликт расписания на YYYY-MM-DD: время … пересекается…».
  • AJAX: 422, поле errors.patterns (+ message). Non-AJAX: 302 + session errors по patterns (не пустой 200).
Поля строки календаря при привязке абонемента (flexible / fixed / разовое): starts_at = дата занятия; ends_at = конец периода назначения (user_lesson_packages.ends_at). У пробного: ends_at = starts_at (один день).
Длинный ends_at у строки не означает «ученик занят этим слотом все подходящие дни недели до конца периода». В конфликт и отображение календаря входит только дата starts_at. Иначе «хвост» периода после последнего занятия блокировал бы новый фикс на том же weekday/времени.

Кросс-слотовое сравнение часов есть только у assign-fixed. Гибкий, разовое и пробное проверяют дубликат «тот же team_schedule_slot_id + starts_at», без пересечения времени между разными слотами в один день.

Тесты: LessonPackageSchoolScheduleAssignmentsValidationFeatureTest, LessonPackageSchoolScheduleFixedOverlapAjaxContractFeatureTest, LessonPackageSchoolScheduleFixedOverlapNonAjaxSafetyNetFeatureTest, BladeInlineJsSyntaxTest::test_school_schedule_fixed_bind_inline_script_is_valid_javascript. UI/API — school-schedule-calendar § конфликт.

UI календаря школы: привязка выполняется inline в модалке слота (отдельная модалка #schoolCalFixedModal снята с UI). Список подходящих назначений — в GET …/slot-user-bind-actions → fixed.existing_assignments; при одном назначении кнопка в две строки ("название" (остаток N)), но форма «Шаблон привязки» (patterns[]) всё равно обязательна; при нескольких — select в #schoolCalSlotFixedFormWrap. Submit — POST …/assign-fixed. Подробности — в разделе «Расписание школы» (§ «Фиксированные абонементы в модалке слота», inline-панели).

Важно: при успешной привязке фиксированного (как и гибкого или разового) абонемента поле lessons_remaining в user_lesson_packages не уменьшается — см. раздел ниже.

Остаток занятий (lessons_remaining) и календарь

Баланс абонемента хранится в user_lesson_packages.lessons_remaining и lessons_total.

  • Привязка к календарю школы (POST привязки гибкого, фиксированного или разового занятия) только создаёт записи в user_team_schedule_slots и при необходимости задаёт период назначения; lessons_remaining при этом не меняется.
  • Списание и возврат остатка выполняются при сохранении статуса занятия в календаре школы для записи с абонементом (вручную администратором или автоматически — см. §Автосписание): учитывается флаг consumes_lesson у статуса и предыдущий статус по тому же слоту/дате/ученику (дельта −1 / +1 / 0). Подробности и таблицы статусов — в разделе про календарь школы.
  • Лимит строк календаря на одно назначение: количество строк user_team_schedule_slots с данным user_lesson_package_id не может превысить lessons_total. Для гибкого и разового это проверяется перед каждой новой привязкой; для фикса длина создаваемой цепочки считается от оставшегося «бюджета» занятий.

Автосписание (lesson_packages.auto_attendance_enabled)

Настройка живёт только в шаблоне абонемента (lesson_packages), не в назначении (user_lesson_packages). Доступна для типов fixed и flexible; для no_schedule (разовое занятие) чекбокс скрыт, значение принудительно false, API вернёт 422 при попытке включить.

UI шаблона

Вкладка «Абонементы» (/admin/lesson-packages и дубль /admin/directories/lesson-packages, view admin/lessonPackages/tabs/packages.blade.php): в модалках «Добавить абонемент» и «Редактировать абонемент» — чекбокс «Автосписание» (#create_auto_attendance_enabled, #edit_auto_attendance_enabled). Подсказка: в конце календарного дня занятия автоматически ставится статус «Посетил» и списывается занятие, если статус не был выставлен вручную.

Правила автоматики

Ежедневно в 00:05 по часовому поясу Europe/Moscow планировщик Laravel ставит в очередь job App\Jobs\AutoMarkYesterdayLessonOccurrencesJob (очередь default, см. мониторинг очередей). Job обрабатывает занятия за вчерашний календарный день (user_team_schedule_slots.starts_at).

УсловиеПоведение
Шаблон с auto_attendance_enabled = true, тип fixed или flexible Запись кандидат на автосписание
Есть хотя бы одно событие user_lesson_occurrence_status_events по паре слот + дата + ученик + user_lesson_package_id Пропуск (ручной или любой статус не перезаписывается)
Пробное (is_trial_lesson = true) или разовое (schedule_type = no_schedule) Вне scope автоматики
Дата исключена из слота (team_schedule_slot_exceptions) или слот неактивен на дату (TeamScheduleCalendarService::slotActiveOnDate) Пропуск — занятие не считается состоявшимся в расписании школы
lessons_remaining = 0 (недостаточно остатка для «Посетил») Пропуск, запись в storage/logs/queue.log; job продолжает обработку остальных строк
Оплата назначения (is_paid / is_manual_paid) Не проверяется

При успешной автоматике создаётся событие статуса «Посетил» (lesson_occurrence_statuses.code = attended, consumes_lesson = true) через тот же сервис, что и ручная отметка — App\Services\LessonPackages\UserLessonOccurrenceStatusService. Поле created_by в событии — NULL (система). Списание остатка — та же дельта, что при ручном «Посетил» (UserLessonPackageConsumptionAdjuster). Повторный запуск job идемпотентен: второй проход не создаёт дубль и не списывает повторно.

Аудит: my_logs, событие schedule.occurrence_status_auto_set (audit-my-logs).

Код и расписание

  • Выборка и eligibility: App\Services\LessonPackages\AutoMarkYesterdayLessonOccurrencesService (processForDate, isEligible).
  • Job: App\Jobs\AutoMarkYesterdayLessonOccurrencesJob — опциональный параметр даты для тестов; в проде — «вчера» по Moscow.
  • Регистрация в App\Console\Kernel: dailyAt('00:05')->timezone('Europe/Moscow')->withoutOverlapping(30).
  • Ручная установка статуса в календаре: LessonPackageSchoolCalendarOccurrenceStatusController::store → тот же UserLessonOccurrenceStatusService.

Журнал /schedule с 2026‑07 читает те же user_team_schedule_slots и пишет статусы через тот же UserLessonOccurrenceStatusService (списание остатка едино). См. schedule-journal.

Сервис

Логика выставления дат инкапсулирована в App\Services\UserLessonPackageCalendarPeriodService::applyFirstCalendarAnchor; ручная смена даты окончания — ::updateEndsAt.

Пробные занятия (trial) в календаре школы

Пробное занятие не является назначением абонемента. Это отдельная запись в user_team_schedule_slots с is_trial_lesson = true и user_lesson_package_id = NULL; у записи задаётся пробный баланс trial_lessons_remaining / trial_lessons_total (обычно 1/1). Списание пробного баланса и флаг «пробное уже использовано» у ученика описаны в разделе про календарь школы.

Разовое занятие (no_schedule)

Шаблон абонемента с lesson_packages.schedule_type = no_schedule. Назначение ученику — строка user_lesson_packages с lessons_total / lessons_remaining (обычно 1/1) и индивидуальной стоимостью fee_amount.

  • Страница «Назначения» (POST /admin/lesson-packages/assignments, UI — §assignments-tab): создаётся назначение без периода (starts_at/ends_at = NULL). Привязка к календарю — отдельным шагом.
  • Модалка слота календаря школы (POST …/school-schedule/single-lesson-registration): если у ученика уже есть свободное назначение (mode=bind_existing), выполняется только привязка к слоту (при одном назначении — две строки на кнопке «Добавить разовое занятие», см. формат подписи); иначе (mode=create_new) в одной транзакции создаётся назначение и строка календаря. Подробности UI и API — в разделе «Расписание школы».
  • Legacy-модалка #schoolCalSingleModal: привязка уже существующего назначения через POST …/assign-single-lesson (выбор user_lesson_package_id). Основной сценарий для администратора — модалка слота.

Период назначения (starts_at/ends_at) задаётся при первой привязке к календарю через UserLessonPackageCalendarPeriodService::applyFirstCalendarAnchor, как у гибкого абонемента. Списание lessons_remaining — только через статус занятия с consumes_lesson.

Отмена записи в календаре (DELETE …/single-lesson-registration/{userTeamScheduleSlot}) удаляет строку user_team_schedule_slots, но не удаляет назначение user_lesson_packages — его можно снова привязать к другому слоту. Если статус уже списывал занятие, остаток восстанавливается (+1).

Таблица и колонки

Таблица #ulp-assignments-table, пресет KidsCrmDataTable.create, класс dt-columns-managed.

Порядок колонок по умолчанию:

  1. Ученик — клик по имени открывает модалку «Изменение абонемента» (класс js-ulp-assignment-edit, KidsCrmTooltip.renderLink)
  2. Группа (user_lesson_packages.team_id → teams.title; при отсутствии — «—»)
  3. Сумма (fee_amount, формат «N руб»)
  4. Оплачен (бейдж; ручная отметка — подпись «руч.» и tooltip с комментарием)
  5. Остаток (lessons_remaining / lessons_total)
  6. Ссылка на оплату (кнопка «Скопировать», если T‑Bank настроен и абонемент не оплачен, сумма ≥ 10 ₽)
  7. Абонемент (название шаблона)
  8. Тип абонемента (фиксированный / гибкий / разовое занятие)
  9. Действия (кнопка «Изменить»)

Колонка «Период» (starts_at–ends_at) в таблице не выводится; период виден в модалке редактирования (и редактируется дата окончания — § ручная смена ends_at) и в JSON строки DataTables (поле period, формат j.m.y - j.m.y).

Настройки видимости колонок — per user в user_table_settings, ключ lesson_packages_assignments:

  • GET /admin/lesson-packages/assignments/columns-settings — admin.lesson-packages.assignments.columns-settings.get
  • POST /admin/lesson-packages/assignments/columns-settings — body { "columns": { "student": true, … } }

Ключи колонок: student, team_label, fee, paid, balance, pay_link, package_name, type_label, actions. Скрытая служебная колонка id без переключателя.

При создании назначения поле «Группа» обязательно, если у партнёра ≥2 активных юр. лиц (PartnerLegalEntityMode::isMultiEntity); список групп — GET …/assignments/teams-for-user?user_id=. Маршрутизация оплаты — payments §2.3.
