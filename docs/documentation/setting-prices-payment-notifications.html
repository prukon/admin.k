Установка цен → «Уведомления»

Файл: /docs/documentation/setting-prices-payment-notifications.html. CRM: /admin/setting-prices/notifications (вкладка в admin/SettingPrices/index, рядом с «По месяцам» / «По ученикам» / «Доп. платежи»). Связано: setting-prices-monthly-users, postpay, payments § users_prices, reports-admin §8.
Кратко. Конструктор правил email-уведомлений по неоплаченным месячным начислениям users_prices в разрезе типов абонементов (fixed / flexible / postpay). Письма — на email ученика, отдельно на каждую строку начисления. Cron: ежедневно 10:00 Europe/Moscow. Журнал писем — отчёт «Исходящие письма» с фильтром категории «Уведомления об оплате» (email_category=payment_notification).

1) Право

  • setPrices.paymentNotifications.manage — вкладка + CRUD правил + превью + тест-отправка.
  • Группа setPrices, is_visible=0, не в базовых ролях (user / admin / trainer) — opt-in через матрицу прав.
  • Миграция каталога: 2026_08_12_100200_add_set_prices_payment_notifications_manage_permission.php (ролям не выдаёт).
  • Нужен также доступ к разделу: setPrices.view (внешний middleware-группа маршрутов).
  • Вкладка в UI: @can('setPrices.paymentNotifications.manage').

3) Модель правила

Таблица payment_notification_rules (partner-scoped):

ПолеСмысл
nameНазвание в UI
is_enabledВкл/выкл (также toggle без полного update)
schedule_typesJSON: подмножество fixed, flexible, postpay (no_schedule в конструкторе нет)
trigger_typeday_of_month или days_after_overdue
trigger_valueДень 1–31 или N дней просрочки 1–90
billing_month_offsetТолько для дня месяца: 0 = текущий календарный месяц (MSK), -1 = предыдущий. Для overdue игнорируется (месяц вычисляется)
subject_template / body_html_templateШаблоны с переменными {{…}}

3.1) Триггер «день месяца»

  • Срабатывает, если день «сегодня» (MSK) равен trigger_value.
  • В коротких месяцах дни 29–31 не наступают — правило в эти дни не шлёт.
  • billing_month_offset=0: целевой users_prices.new_month = 1-е число текущего календарного месяца.
  • billing_month_offset=-1: целевой месяц = предыдущий календарный.
Пример постоплаты. Абонемент за сентябрь, правило «1-е число / предыдущий месяц»: письмо 1 октября (целит сентябрь). 1 ноября это же правило целит октябрь — сентябрьскую строку повторно не берёт. Для повторных напоминаний по сентябрю нужны другие правила (другой день или days_after_overdue).

3.2) Триггер «дней после начала просрочки»

Для всех типов абонементов в правиле (включая postpay) старт просрочки единый: 1-е число следующего месяца после биллинг-месяца M. Пример: абонемент за сентябрь → 1-й день просрочки = 1 октября, 3-й = 3 октября. Правило срабатывает только когда сегодня − (N−1) приходится ровно на 1-е число месяца.
Отдельной «постоплатной» даты старта просрочки в коде нет. Разница postpay vs предоплата задаётся админом через календарные правила (день + offset −1) и формулировки шаблонов.

4) Аудитория рассылки

  • Строки users_prices партнёра за целевой new_month (join users.partner_id + lesson_packages).
  • price_cents > 0, effective_is_paid = false (ручной is_manual_paid важнее авто is_paid — как в отчёте задолженностей).
  • Есть lesson_package_id, schedule_type шаблона ∈ schedule_types правила.
  • Email ученика валиден; иначе запись dispatch = skipped (missing_or_invalid_email), письмо не ставится в очередь.
  • Одно письмо на каждую подходящую строку users_prices.
  • Перед отправкой из job повторная проверка: если уже оплатили / сумма 0 → skipped (already_paid_or_zero).

5) Расписание и идемпотентность

  • Cron: DispatchPaymentNotificationsJob → timezone('Europe/Moscow')->dailyAt('10:00')->withoutOverlapping(55) (app/Console/Kernel.php).
  • Ручной запуск: php artisan payment-notifications:dispatch --date=YYYY-MM-DD [--sync].
  • Таблица payment_notification_dispatches: UNIQUE (payment_notification_rule_id, users_price_id, trigger_date) — повторный прогон в тот же календарный день не дублирует письма.
  • Отправка: SendPaymentNotificationDispatchJob → PaymentNotificationMail с заголовками X-Partner-Id, X-Email-Category: payment_notification.

6) Шаблоны и переменные

В модалке правила — ссылка «Переменные шаблона» (скрываемый блок по умолчанию, паттерн как «Как это работает» при создании договора на /client-contracts).

  • {{student_name}}, {{student_firstname}}, {{student_lastname}}
  • {{month}}, {{month_year}} — из users_prices.new_month (locale ru, Europe/Moscow)
  • {{amount}} — Money::formatRub(price_cents)
  • {{team}} — teams.title
  • {{package}} — lesson_packages.name
  • {{package_type}} — человекочитаемый тип

Значения переменных экранируются; HTML-разметка шаблона сохраняется. Базовая обёртка письма (resources/views/emails/payment-notification.blade.php): логотип img/logo.png сверху и футер «С уважением, Команда kidscrm.online» — как в welcome-письмах клиента.

7) UI вкладки

  • Текст шапки: «Правила email-рассылки:» / «Абонемент не оплачен.» / «Отправка в 10:00 (Europe/Moscow).»
  • Дефолты «Добавить правило» (openCreate): типы fixed+flexible, день месяца = 5, offset = текущий, правило включено.
  • При триггере overdue блок «Месяц начисления» скрывается (syncTriggerUi).
  • Превью без users_price_id — демо-данные: текущий календарный месяц MSK + полная обёртка в email_html (iframe). Поле «Месяц начисления» правила на демо не влияет.
  • Превью с users_price_id — подстановка из реальной строки начисления.

8) Типовые наборы правил (рекомендации)

  1. Предоплата reminder: fixed+flexible, день 5, offset 0, шаблон «плановая оплата».
  2. Предоплата soft overdue: fixed+flexible, день 25, offset 0.
  3. Предоплата hard overdue: fixed+flexible, days_after_overdue = 3.
  4. Постоплата выставление: postpay, день 1, offset −1.
  5. Постоплата просрочка: postpay, день 6, offset −1.
