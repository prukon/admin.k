Кошелёк партнёра

Страница /partner-wallet · право partnerWallet.view · обычная CRM-страница (STRICT_CURRENT).
Админ школы видит баланс и историю только своей школы. Superadmin — кошелёк школы, выбранной в переключателе. Источник партнёра — PartnerContext, не Partner::first().

1) Доступ

  • Маршруты в группе auth + 2fa + can:partnerWallet.view.
  • Право в базовой роли admin (config/role_base_permissions.php), группа permissions partner.
  • Без права — 403 (JSON и web). Гость — 302 на логин / 401 JSON.
  • Non‑superadmin без partner_id: middleware SetPartner → 302, guest, session errors.email = «Ваша организация недоступна.»

2) Изоляция по партнёру

ПоверхностьЧто ограничено
GET /partner-wallet Баланс из partners.wallet_balance_cents текущего партнёра (две копейки); hidden partner_id = current.
GET /partner-wallet/transactions DataTables: WHERE partner_id = current. Чужие строки не попадают в data / recordsTotal.
POST /partner-wallet/topup CreatePartnerWalletTopupRequest: partner_id обязан совпасть с current — иначе 422 errors.partner_id «Нельзя пополнить кошелёк другой школы.» (до ЮKassa запись не создаётся). guardPartnerAccess() — запасной 403 «Нет доступа к кошельку этой школы.», если ID всё же не совпал; в одном запросе после 422 до guard очередь не доходит. Запись транзакции — partner_id из PartnerContext, не из тела запроса и не Partner::first().
GET /partner-wallet/success То же право partnerWallet.view. Страница не знает статус платежа — пишет «Платёж обрабатывается»; зачисление делает вебхук.
POST /partner-wallet/webhook, POST /webhook/yookassa (scope partner_wallet_topup) Публично, без auth/CSRF, фильтр IP ЮKassa. Это не STRICT_CURRENT: одна транзакция по metadata.wallet_transaction_id, зачисление на tx.partner_id. Не список всех школ.
Не-superadmin не может подменить школу через session: middleware SetPartner фиксирует current_partner = user.partner_id.

3) Деньги

  • БД: partners.wallet_balance_cents, partner_wallet_transactions.amount_cents.
  • Форма пополнения принимает рубли; HTML min="1"; Request: required|numeric|min:1|max:99999999.99, сообщение «Сумма должна быть не меньше 1 ₽.»
  • Запись — Money::toCentsOrFail.
  • На странице баланс рендерится из wallet_balance_cents, не из legacy wallet_balance, всегда две копейки (number_format(..., 2)).
  • Сайдбар: тот же wallet_balance_cents текущего партнёра (app('current_partner')), без копеек (number_format(..., 0)). Это отображение, не другая колонка БД.

4) Ошибки пополнения

  • Валидация в CreatePartnerWalletTopupRequest (rules / attributes / messages).
  • AJAX (postJson / X-Requested-With): 422, тексты из errors[field] под полями (data-error-for="amount", data-error-for="partner_id"), не alert().
  • Non-AJAX POST без JS: валидация → 302 на /partner-wallet + session errors[field] (не пустой 200). Успешный/шлюзовой путь создаёт pending в partner_wallet_transactions текущей школы и отвечает JSON 200/500 (как SMS send: не 302 на ЮKassa, пока контроллер всегда response()->json).
  • Client::setAuth() вызывается до try. Не-int / битый yookassa.shop_id → TypeError без pending-строки. Если auth прошёл, а createPayment упал — JSON 500 и pending своей школы уже есть.

5) UX страницы

  • Первое открытие и повторный GET: поле суммы без value (пусто, не подставляется чужая сумма).
  • Порядок: сумма → кнопка «Оплатить»; история — DataTables #walletTxTable.
  • Сайдбар @can('partnerWallet.view'): ссылка «(пополнить)» только с правом; без партнёра — «Партнёр не выбран».
  • Один JS-путь submit: $('#walletTopupForm').on('submit') + e.preventDefault + $.ajax.

6) После оплаты и вебхуки

  • YooKassa return_url — /partner-wallet/success. Контроллер ykWalletSuccess не опрашивает шлюз: «Платёж обрабатывается. Статус обновится в истории транзакций в течение минуты.»
  • Зачисление: payment.succeeded → tx.status = succeeded + partners.wallet_balance_cents += amount_cents (lockForUpdate по партнёру транзакции).
  • payment.canceled → статус canceled, баланс не трогаем. Уже финальный статус — идемпотентный {ok:true}.
  • Расхождение суммы вебхука и tx.amount_cents → 422, без зачисления.
  • Два входа (оба в CSRF except): PartnerPaymentController::ykWalletWebhook на /partner-wallet/webhook и YooKassaWebhookController на /webhook/yookassa (ветка metadata.scope === partner_wallet_topup). Логика зачисления одинаковая.
