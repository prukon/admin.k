Право groups.own: только свои группы (тренер)

Файл: /docs/documentation/groups-own.html · анонс /doc#groups-own-index
Отдельное видимое право матрицы (is_visible=1, группа users, sort_order=42, описание «Только свои группы (тренер)»). В config/role_base_permissions.php не входит — ни trainer, ни admin, ни user. Школа включает его роли тренера, когда фильтры и списки групп должны сужаться до team_trainer. Без права тренер с рабочими правами (users.view / schedule.view / groups.view) видит все группы школы, как раньше.

1) Когда срабатывает

Сервис App\Services\TrainerOwnTeamsScope. Ограничение включается, если актор can('groups.own') и у него есть профиль trainer_profiles. Superadmin проходит Gate::before (право «есть»), но без профиля тренера isRestricted() = false — списки не режутся. Админ школы без trainer_profiles тоже не режется, даже если право выдано роли. Список разрешённых групп: team_trainer текущего партнёра. Нет привязанных групп — пустой список, не «все группы школы».

Gate: AuthServiceProvider — Gate::define('groups.own', …). Правило валидации: App\Rules\AllowedActorTeam — текст «Выберите группу из списка.» под полем (422). Миграция: 2026_09_11_021700_add_groups_own_permission.php. Каталог hints: config/permission_capability_hints.php.

2) Что режется

МестоПоведение при включённом праве
Селекты / фильтры групп, /admin/teams Только группы из team_trainer. Карточка/update/delete чужой группы той же школы — 403. Группа другого партнёра — 404 (where('partner_id') + firstOrFail).
Клиенты /admin/users, журнал /schedule Режим «все» — только ученики своих групп. Чужой team_id / ?team=: AJAX/JSON — 422 под полем «Выберите группу из списка.»; native GET журнала — 302 + errors.team (не 200 с чужими учениками).
Подписи и чекбоксы групп ученика Пересечение: видна только группа тренера. JSON team_ids / колонка «Группы» — без чужих названий.
Сохранение team_ids ученика Merge: чужие группы не снимаются. TrainerOwnTeamsScope::mergeSubmittedStudentTeamIds (CRM update и POST /schedule/user/{user}/sync-teams). Create: StoreRequest принимает team_ids без users.group.update (модалка create передаёт canEditTeams=true); edit без этого права — select disabled.
Чат Оба селекта (#contactsTeamFilter, #createGroupMembersTeamFilter) — только свои группы. Пустой фильтр: сотрудники школы видны, ученики — только своих групп. team_id=none — люди без строк в team_user (в т.ч. сотрудники без групп).
Консоль First-paint «Все группы» и getTeamDetails?teamName=all — ученики своих групп, без чужих и без «без группы». «Без группы» (withoutTeam) — все ученики школы без pivot (строки не режутся правом). Карточка своего / без группы — getUserDetails success: true; чужой ученик / чужая группа — 200 JSON success: false (не 422).
Создание группы TeamController@store авто-attach’ит профиль актора в team_trainer, иначе он свою новую группу не увидит. AJAX — JSON 200 {message, team:{id,title}}; native POST — 302 на index + запись.
Прочие селекты групп restrictTeamsQuery: заявки с сайта, договоры, отчёты (в т.ч. GET …/payments/teams-search), установка цен, карточка тренера, объекты, шаблоны абонементов, ЛК аккаунта. Список строк заявок/договоров/ЗП/нагрузки/отчётов без выбранной группы этим правом не режется. Чужой filter_team_id в отчёте платежей игнорируется (как «все»), не 422.

3) Что не режется этим правом

  • Строки заявок с сайта, договоров, ЗП, нагрузки других тренеров, отчётов — отдельные права раздела; без выбранной группы список не сужается до «своих учеников».
  • Ученики без группы — отдельный фильтр «Без группы» / none / withoutTeam; в консоли карточка такого ученика открывается (allowsStudent(..., allowWithoutTeam: true)).
  • Публичный лендинг, регистрация, «Моя группа» клиента.
