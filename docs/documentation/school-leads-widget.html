Заявки с сайта: виджет (iframe) и CRM

Файл: /docs/documentation/school-leads-widget.html · оглавление: /doc · иерархия: directories-hierarchy · см. также страница заявки партнёра (лендинг)
Назначение: сбор заявок клиентов школы в CRM (school_leads) двумя публичными каналами:
  • Виджет iframe (/widget/{widgetKey}) — короткая форма для встраивания на сайт партнёра (§4).
  • Страница заявки (/lead/{landingSlug}) — брендированный лендинг с полной формой; slug задаёт партнёр в CRM; подробно в school-leads-landing.html.
Заявки изолированы по partner_id и отображаются в кабинете школы (/admin/school-leads).
После создания клиента из лида статус заявки по-прежнему меняется (таблица и модалка) — §5.5.4; кнопка «Создать клиента» показывает в ховере все обязательные поля — §5.7. Автосопоставление родителя из справочника при заявке с лендинга — §5.5.5.
В таблице: порядок ребёнок → родитель → статус → объект → секция → телефон, затем остальные (в т.ч. «Договор»); без колонки «Действия»; правка по клику на ФИО родителя; удаление заявок из CRM недоступно — §5.5.3, анонс /doc.
Не путать с разделом «Лиды партнёров» (/admin/partner-leads, таблица partner_leads) — там B2B-заявки с лендинга kidscrm «подключить школу к платформе».

2) Модель данных

  • partner_widgets — одна запись на партнёра: widget_key (iframe, 48 символов), landing_slug (публичный адрес лендинга, 3–40 символов, задаётся в CRM), landing_key (служебный, не в URL), is_active, is_landing_active. Создаётся при создании партнёра (Partner::created → PartnerWidgetService::ensureForPartner).
  • school_lead_statuses — справочник статусов заявок (§5.4): системный «Новый» (partner_id = null, code = new, read-only) + кастомные статусы партнёра (имя, цвет, sort_order, is_default_in_filter). Soft delete.
  • school_leads — заявки: partner_id, source (widget | landing), name, phone, school_lead_status_id (FK на school_lead_statuses, nullable), поля родителя/ребёнка (лендинг), parent_id (nullable FK на parents, автосопоставление с лендинга — §5.5.5), parent_match_reason / parent_match_count / parent_match_confirmed, location_id, sport_type_id (лендинг, nullable), team_id (лендинг), флаги особенностей, needs_contact_help, user_id (nullable — ученик после конвертации), UTM, page_url, referrer, согласие ПДн (consent_accepted_at, policy_url — у лендинга null), SoftDeletes на модели (legacy; из CRM удаление заявок недоступно — §5.5.3). Миграции: 2026_05_29_100001_add_extended_fields_to_school_leads_table.php, 2026_05_29_120002_add_sport_type_id_to_school_leads_table.php, 2026_06_16_140000_create_school_lead_statuses_and_migrate_school_leads.php (таблица статусов, FK, удаление колонки status enum), 2026_08_07_010000_add_parent_match_to_school_leads_table.php.
  • partner_telegram_link_tokens — одноразовые токены для привязки Telegram через /start (срок жизни ~30 мин).
  • partners.school_leads_telegram_chat_id — Chat ID для уведомлений партнёра в Telegram.

Поля лендинга и публичные маршруты /lead/… — school-leads-landing.html.

3) Права и меню

В /config/role_base_permissions.php для роли admin (в разрезе партнёра):
  • schoolLeads.view — страница «Заявки с сайта», datatable, update/delete заявок, CRUD настраиваемых статусов (§5.4). В базовый набор входит.
  • schoolLeadLanding.view — вкладка «Страница заявки», настройка landing_slug, ссылка /lead/{landingSlug}. В базовый набор входит.
  • schoolWidget.view — вкладка «Виджет для сайта», код iframe, подключение Telegram. В базовый набор не входит — назначается отдельно (право с is_visible = 0).

Роль user этих прав не получает по умолчанию. Назначение — через «Права и роли» или сидеры (см. партнёры: базовые права).

3.1) Счётчик «Новых» в сайдбаре

У пункта левого меню «Лиды» справа может отображаться badge с числом неудалённых заявок текущего партнёра в системном статусе «Новый» (school_lead_status_id = id записи с code = new). Критерий тот же, что у счётчика «Новых» в toolbar вкладки «Заявки» (leadStats.new / stats.new в JSON, метод SchoolLeadController::buildPartnerLeadStats).

АспектПоведение

Отдельная полная форма на /lead/{landingSlug} — не этот раздел; см. school-leads-landing.html.

    • Сброс — возвращает статусы по умолчанию (is_default_in_filter), очищает район, объект, секцию и чекбокс особых условий.

5.1.3) Аудит (my_logs)

Запись — через AuditLogger (audit-my-logs). События: school_lead.updated; исторически также school_lead.deleted (категория school_lead; новые удаления заявок из CRM не пишутся — endpoint удалён). Создание заявки с лендинга/виджета в CRM-лог не пишется — только действия на вкладке «Заявки».

  • update — diff «старое → новое» по названию статуса заявки, комментарию, району, объекту; лог только при изменениях.
  • delete (только история) — «Заявка удалена: Заявка #{id}: {ФИО}.» (level = security). Новые события из CRM не пишутся: endpoint удаления заявки снят (§5.5.3).
  • CRUD статусов (§5.4) — отдельные события: school_lead.status_created, school_lead.status_updated, school_lead.status_deleted (категория school_lead).
  • UI — кнопка «История» (иконка fa-clock-rotate-left) в toolbar → GET /admin/school-leads/logs-data (route('logs.data.school-lead')), модалка includes.logModal.

5.1.4) «Показать N» — персонально на пользователя

Селект DataTables «Показать 10 / 20 / 50 / 100» на вкладке «Заявки» сохраняется на текущего пользователя с правом schoolLeads.view в user_table_settings.page_length для table_key = school_leads_index (та же строка, что видимость колонок). Номер страницы (start) не хранится.

  • Старт. SchoolLeadController::index читает page_length текущего пользователя и передаёт $leadsPageLength в Blade. KidsCrmDataTable.create получает dataTable.pageLength и columnsSettings.persistPageLength: true. Нет записи / значение не из 10, 20, 50, 100 → 10 (UserTableSetting::resolvePageLength).
  • Смена селекта. Пресет слушает length.dt и делает POST /admin/school-leads/columns-settings только с page_length (колонки в этом запросе не отправляются и не затираются). Request: SchoolLeadColumnsSettingsSaveRequest.
  • Ошибки. Невалидное значение: AJAX → 422 errors.page_length («Можно показать 10, 20, 50 или 100 записей.»), текст под .dataTables_length (.kids-dt-page-length-error). Non-AJAX → 302 + session errors. Пустой POST по-прежнему 422/302 по columns.
  • GET columns-settings не отдаёт page_length — контракт видимости колонок { ключ: bool } / [] не менялся. Сохранение колонок не сбрасывает page_length.
  • Лендинг и виджет заявок без opt-in. Полный список страниц с persistPageLength: true (ученики, отчёты, выплаты T‑Bank) — /doc. Остальные админские таблицы на пресете не пишут N, пока нет persistPageLength: true и поддержки page_length в их columns-settings.

Тесты: SchoolLeadsPageLengthFeatureTest (HTTP 200/403/422/302, UX: повторное открытие страницы держит N, скрытие колонок не сбрасывает N, start не пишется, лендинг/виджет без opt-in), SchoolLeadsPageLengthFullAccessFeatureTest (гость / без права / viewer / admin; PUT/PATCH/DELETE → 404/405), BladeInlineJsSyntaxTest::test_kids_datatable_page_length_persist_posts_only_page_length_not_page_number (POST только page_length, без columns/start), BladeInlineJsSyntaxTest::test_only_opted_in_blades_enable_page_length_persist.
