Право lessonPackages.type.postpay

Файл: /docs/documentation/lesson-packages-type-postpay.html. Бизнес-логика постоплаты — postpay; матрица групп — settings-permission-groups; базовые роли — partners-permissions.
С 2026‑08 выбор типа абонемента schedule_type = postpay («Постоплата») отделён от общего lessonPackages.view / setPrices.view. Без этого права нельзя создать шаблон postpay, сменить тип на postpay и назначить postpay-пакет в «Установка цен». Уже созданные шаблоны и уже назначенные месяцы продолжают работать.

1) Право

ПолеЗначение
ИмяlessonPackages.type.postpay
Описание (сидер)Абонементы, тип «Постоплата»
Группа матрицыlessonPackages («Абонементы»)

Миграция2026_08_04_170000_add_lesson_packages_type_postpay_permission.php — только создаёт право, никому не выдаёт
Базовые ролиВ config/role_base_permissions.php для user / admin / trainer не входит (строка закомментирована)
После выката право нужно выдать вручную (superadmin / SQL в permission_role), иначе option «Постоплата» скрыт и новый выбор postpay недоступен. Существующие postpay-шаблоны и уже назначенные users_prices.lesson_package_id не удаляются.

2) Что закрывает

ПоверхностьБез праваС правом (+ родительские права раздела)
Шаблоны: option «Постоплата» в create / edit / фильтре типа (packages.blade.php, дубль в «Справочниках») Option скрыт (@can). При открытии уже postpay-шаблона в edit option добавляется JS-ом, чтобы значение не «терялось» Option виден
POST/PUT …/lesson-packages с schedule_type=postpay 422 на schedule_type («Недостаточно прав для выбора типа «Постоплата»»). Исключение: update уже существующего postpay-шаблона без смены типа — разрешён AJAX → 200 JSON; non-AJAX → 302 на index
DataTables фильтр schedule_type=postpay Пустой результат (даже при crafted query) Строки postpay
Select абонемента на вкладке «Назначение абонементов» (ULP) Postpay-пакеты не попадают в список (backend и так всегда 422 на store ULP) В списке могут быть, store всё равно 422 (доменный запрет ULP)
«Установка цен»: каталог lessonPackages (monthly / getTeamPrice / year) Postpay скрыты, кроме уже назначенных в team_prices / users_prices (чтобы текущие select не пустели) Все postpay-шаблоны партнёра
setTeamPrice, setPriceAllUsers, setPriceAllTeams, saveUserYearPrices с postpay lesson_package_id 422 на поле пакета при новом выборе. Повторная отправка того же уже назначенного id — разрешена Ожидаемые 200 / 302
Не закрывает этим правом (нужны другие права + уже назначенный postpay-месяц): журнал create_postpay (schedule.view), лок ячеек после оплаты, оплата с консоли (postpay_pay_available). Это сценарии работы с уже выставленной постоплатой, а не выбор типа шаблона.
