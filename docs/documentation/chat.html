Чат CRM (Сообщения)

Файл: /docs/documentation/chat.html · кабинет: /chat · анонс чата: /doc#chat-index · онлайн / карточка: /doc#chat-presence-index · черновик: /doc#chat-draft-index · оверлей Reverb: /doc#reverb-status-overlay-index
Кратко. Личные диалоги 1-на-1 внутри текущей школы. Текст без вложений. Пункт «Чат» в сайдбаре, бейдж badge-info — число непрочитанных (скрыт при 0). Онлайн — зелёная точка (в списке диалогов красной нет), галочки только у исходящего, карточка собеседника из шапки открытого диалога. Неотправленный текст — черновик на сервере, в списке превью «Черновик: …» (анонс). Realtime — тот же Reverb, что у колокольчика. Если сокет недоступен, страница чата подтягивает новые сообщения опросом раз в 1 секунду; на остальных страницах бейдж — раз в 12 секунд.
Не путать с колокольчиком in-app уведомлений (in-app-notifications) и с email «Установка цен → Уведомления». Не путать черновик сообщения с черновиком ЗП тренеров (схема Канзас). Групповые чаты в этой версии нет (отложено).

2) Как это выглядит

  1. Сайдбар: «Чат» (иконка конверта). Бейдж js-chat-unread-count с классом badge badge-info (не красный), скрыт при 0, иначе точное число непрочитанных. Живое обновление: сокет inbox.bump / thread.read. Если WebSocket не connected: на странице чата — опрос inbox и открытого диалога раз в 1 секунду (KidsCrmChatRefreshInbox); на остальных страницах — GET /chat/api/unread раз в 12 секунд. Без перезагрузки страницы. Если открыт тот же диалог, бейдж не вспыхивает (из unread_total вычитается unread этого треда).
  2. Слева — список диалогов (непрочитанные выше, затем по времени). Поиск по фамилии и имени собеседника и превью. Заголовок диалога, шапка и GET /chat/api/threads/{id} — users.lastname + users.name (если фамилии нет — только имя). Клиент при открытии диалога перезаписывает title в списке слева из этого ответа, поэтому колонки собеседника те же, что у списка (ChatService::PEER_USER_COLUMNS, с lastname). Справа сверху — время последнего сообщения (сегодня ЧЧ:ММ, иначе дата). Под временем, справа внизу — каунтер непрочитанных (.chat-li-unread, фон #f3a12b); при 0 не показываем. Если последнее сообщение исходящее: одна серая галочка слева от времени, пока собеседник не прочитал, две зелёные — после прочтения (как в пузыре сообщения). Если собеседник онлайн (last_seen_at не старше 2 минут) — зелёная точка справа снизу на аватарке списка. Офлайн в списке точку не рисуем. Если у текущего пользователя есть неотправленный текст — превью Черновик: … вместо последнего сообщения (.chat-li-preview.is-draft, цвет #f3a12b), время справа остаётся last_message_time. Черновик свой, на сервере; собеседник его не видит. Клик по строке открывает диалог (openThread), подставляет черновик в поле и сразу ставит фокус в #msgInput (после setComposerEnabled(true)). Подробнее — §2.1, черновик — §2.2 / анонс.
  3. «Контакты» открывает модалку контактов текущей школы (стандартная ширина Bootstrap, список до 60vh / 520px со скроллом). Справа снизу аватарки: зелёная точка если онлайн, красная если офлайн (в том числе если человек ещё ни разу не пинговал после появления last_seen_at). После аватарки три колонки: слева фамилия и имя (users.lastname + users.name, JSON name; без фамилии — только имя), под ним ФИО родителя серым меньшим шрифтом (parent_full_name, .contact-parent) — только если строка непустая; по центру на одной линии с именем — группы ученика (team_title, .contact-team); справа — роль (.contact-role). Пустую строку родителя не показываем. Поиск ?q= — по фамилии и имени ученика, email, фамилии и имени родителя (parents.lastname / parents.firstname). Отчество родителя и soft-deleted карточка в поиске не участвуют.
  4. Клик по контакту открывает существующий 1-на-1 или создаёт новый. Повторный клик по тому же человеку не плодит диалоги.
  5. Справа — переписка. Композер disabled, пока не выбран диалог. У своих сообщений одна серая галочка, пока собеседник не прочитал, и две зелёные — после прочтения (сокет thread.read; если сокет не connected — опрос is_read раз в 1 секунду на странице чата). Клик по аватарке или имени в шапке открытого диалога открывает модалку карточки собеседника (стандартная ширина Bootstrap): аватар, ФИО (lastname+name), телефон ученика (tel:), ФИО и телефон родителя, последний онлайн («онлайн» / дата-время / «-»), группы. Пустые поля в карточке — «-». Ошибки — под полями (#msgBodyError, в модалке контактов #contactsError, в карточке #peerCardError).
  6. История вверх: прокрутка к верху догружает более старые сообщения.

2.1) Онлайн, галочки исходящего, ФИО родителя, карточка

Анонс на главной: /doc#chat-presence-index.

  1. Онлайн. users.last_seen_at, окно 120 секунд (UserPresence::ONLINE_WITHIN_SECONDS, сравнение gte: ровно 2 минуты ещё онлайн). Никогда не пинговал — офлайн. POST /presence/ping (presence.ping): группа auth+2fa, без can:messages.view. JSON {ok: true} и у AJAX, и у нативного POST (heartbeat, не 302 на раздел). Throttle записи в БД — 30 секунд. Клиент: includes/in_app_notifications/echo.blade.php, ping() при загрузке и setInterval(ping, 60000). Скрипт не содержит route('chat.index'), чтобы HTML dashboard без права чата не тащил URL /chat.
  2. Список диалогов. Заголовок и шапка — lastname+name (без фамилии — только имя). Время справа сверху — last_message_time (сегодня часы:минуты, иначе ДД.ММ.ГГ), поле last_seen_at в payload списка нет. Каунтер непрочитанных — .chat-li-unread справа внизу под временем, цвет #f3a12b; при 0 не рисуем. peer_is_online → класс chat-online-dot; офлайн — без точки и без is-offline. Галочки (ticksHtml) только если last_message_is_mine: непрочитано — checks-sent (одна серая), прочитано — checks-read + check-second. Входящее: last_message_is_read = null, галочек нет. Клик по строке — openThread, не карточка; после включения композера в #msgInput подставляется свой draft_body и ставится фокус. Неотправленный текст: PATCH /chat/api/threads/{id}/draft (поле body, debounce 500 мс на клиенте, сразу при уходе из диалога). В списке при непустом своём draft_body — превью Черновик: … (.chat-li-preview.is-draft, #f3a12b), не последнее сообщение. Собеседник в JSON списка и show видит только свой черновик (чужой не отдаём). Успешная отправка обнуляет черновик отправителя. InboxBump после send несёт draft_body: '' только отправителю (у собеседника ключ не ставим, чтобы не затереть его кэш). Анонс: /doc#chat-draft-index, подробно — §2.2.
  3. Контакты. is_online → contact-online-dot is-online / is-offline (ни разу не seen = красная). Три колонки после аватарки, выравнивание по верху: слева .contact-main (имя и под ним .contact-parent), по центру .contact-team (team_title) на одной линии с именем, справа .contact-role. JSON name — фамилия и имя ученика. Поиск ?q= по users.lastname / users.name / email / parents.lastname / parents.firstname (soft-deleted родитель не матчится). Строка .contact-parent только при непустом parent_full_name; пустую и пробелы не показываем и не рисуем «-». В JSON контактов нет phone / parent_phone / last_seen_at. Soft-deleted родитель → пустое ФИО. Клик по строке — startDialog.
  4. Карточка шапки. #threadPeerHit с классом is-idle, пока диалог не открыт; openPeerCard сразу выходит, если нет currentPeerId. GET /chat/api/users/{user}: full_name, phone, parent_full_name, parent_phone, is_online, last_seen_at, last_seen_label («онлайн» / d.m.Y H:i / «-»), team_title. В UI пустое — «-», телефоны с tel:. Своя школа, в том числе отключённый и сам себе — 200; чужой партнёр — 403. Модалка #peerCardModal стандартной ширины, ошибки в #peerCardError.
  5. Перерисовка. InboxBump отдаёт те же флаги списка, что HTTP inbox. markListOutgoingRead меняет галочки, только если последнее сообщение исходящее.

2.2) Черновик неотправленного текста

Анонс на главной: /doc#chat-draft-index.

  1. Хранение. participants.draft_body — только строка текущего участника. Собеседник в index/show видит пустой свой draft_body, не чужой текст. Trim: пусто и пробелы → NULL в БД, в JSON ''. Максимум 5000 символов (как у сообщения).
  2. Запись. PATCH /chat/api/threads/{thread}/draft, поле body (SaveChatDraftRequest). AJAX 200 ok + draft_body; нативный PATCH — 302 на /chat. Не участник 403, нет треда 404, 422 errors.body (длиннее 5000 / не строка) не затирает прошлый черновик. Пропущенное body стирает. GET/POST/DELETE URI → 404/405. Сохранение не бродкастит inbox.bump.
  3. Список. Непустой свой черновик → превью Черновик: … (.chat-li-preview.is-draft, #f3a12b), не last_message. Время — по-прежнему last_message_time. Поиск слева матчит и draft_body.
  4. Клиент (public/js/chat.js). Debounce 500 мс при наборе; сразу при уходе из диалога. openThread подставляет черновик в #msgInput и ставит фокус. Опрос inbox не затирает поле. Успешный send обнуляет; ошибка отправки возвращает текст и превью. Входящее сообщение собеседника мой черновик не трогает. После send InboxBump с draft_body: '' только отправителю.

Пользователь другой школы в user_id — 422, errors.user_id: «Нельзя добавить пользователя другой организации.» Пустое сообщение — 422 errors.body (AJAX) или 302 с errors.body в сессии (нативный POST). Нативный POST/PATCH без X-Requested-With не отдаёт сырой JSON 200/201 — редирект на страницу чата, запись в БД создана. POST /presence/ping доступен любому залогиненному (включая роли без messages.view): гость 302/401, JSON ok. Пишет users.last_seen_at не чаще чем раз в 30 секунд (клиент пингует раз в 60 секунд из Echo-include на страницах кабинета). POST /presence/ping — heartbeat, не форма раздела: и AJAX, и нативный POST отдают JSON {ok: true} 200 (не 302). GET/PATCH/DELETE этого URI → 404/405, не пустой 200 и не 500.

4) Данные и код

  1. Таблицы пакета messenger: threads, messages, participants (soft deletes). Своя колонка participants.draft_body (nullable text, до 5000 символов) — черновик текущего участника, собеседник её не читает.
  2. Модели: App\Models\ChatThread, ChatMessage, ChatParticipant.
  3. Логика: App\Services\Chat\ChatService. Контроллер тонкий: ChatApiController + Form Request в app/Http/Requests/Chat/.
  4. Контакты: users.partner_id = current_partner, is_enabled=1, без себя. В карточке team_title — группы ученика через UserTeamQuery (см. student-team-membership). is_online — users.last_seen_at не старше 2 минут; parent_full_name — ФИО из справочника parents (пусто, если карточки нет). Поле name в списке контактов и title диалога — lastname+name (без фамилии — только имя). Поиск контактов ?q= ещё по фамилии/имени родителя. Онлайн в CRM обновляется ping POST /presence/ping (Echo-include на всех страницах кабинета, раз в 60 секунд, запись в БД не чаще чем раз в 30 секунд). Карточка шапки: GET /chat/api/users/{id} — full_name, phone, parent_full_name, parent_phone, last_seen_label, team_title.
  5. 1-на-1: тред ровно с двумя участниками (я + собеседник). Повторный POST возвращает тот же thread_id (блокировка пары пользователей). Список диалогов показывает один тред на peer_id, даже если в БД остались старые дубли.

5) Realtime

  1. Каналы (как раньше): thread.{id}, inbox.{userId}, плюс общий user.{id} колокольчика.
  2. События: message.created, inbox.bump (в т.ч. unread_total для бейджа сайдбара), thread.read.
  3. Клиент Echo поднимается в includes/in_app_notifications/echo.blade.php (без лишнего wsPath: '/app': pusher-js сам собирает /app/{key}). Бейдж сайдбара слушает inbox в includes/chat/echo.blade.php. Страница чата — public/js/chat.js (без Vite / npm run build). Если Reverb недоступен, HTTP чата не падает (событие пишется в лог). На странице чата опрос и событие inbox.bump обновляют бейдж меню и превью списка одним тиком (KidsCrmChatRefreshInbox / KidsCrmChatOnInboxBump). Если открыт тот же диалог, бейдж сайдбара не вспыхивает: из unread_total вычитается unread этого треда. Если сокет не connected, страница чата опрашивает inbox и открытый диалог раз в 1 секунду; на остальных страницах бейдж — раз в 12 секунд. Открытие диалога (GET show) сразу отдаёт unread_total; страница чата ставит его в бейдж меню без ожидания сокета. Superadmin видит поверх всех окон бейдж Reverb: процесс — TCP-проверка внутреннего broadcasting.connections.reverb.options (тест 127.0.0.1:6008, прод 127.0.0.1:6009), сокет — состояние Echo через nginx location /app (сниппет nginx.ssl.conf_reverb, не proxy-template laravel-reverb). Процесс down и сокет connecting — не «всё ок» (оверлей is-warn / is-bad, не is-ok). Иконка копирует оба значения в буфер. Отдельный анонс: оверлей статуса Reverb.

5.1) Оверлей статуса Reverb

  1. Только роль superadmin (не @can messages.view). Include includes/chat/reverb_status.blade.php в лейауте admin2 после Echo. На логине и у admin/trainer/user бейджа нет.
  2. Процесс: TCP на broadcasting.connections.reverb.options (тест 127.0.0.1:6008, прод 127.0.0.1:6009), не на публичный :443.
  3. Сокет: Echo. Nginx location /app — сниппет nginx.ssl.conf_reverb, не proxy-template laravel-reverb. Клиент без wsPath: '/app'.
  4. Зелёный только при процессе up и сокете connected. Down + connecting — не «всё ок».
  5. GET /chat/api/reverb-status: JSON listening / ok / host / port / driver. Гость 302/401, не-superadmin 403, мутации 405.
