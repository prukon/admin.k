Саморегистрация школы с лендинга

Файл: /docs/documentation/partner-self-registration.html · анонс: /doc
Публичная форма /partner/register регистрирует школу (партнёра) и первого администратора. Это не регистрация ученика и не переключатель «Регистрация на сайте» в админке (registrationActivity). Кнопка «Регистрация» в шапке лендинга и сама форма управляются флагом PARTNER_SELF_REGISTRATION_ENABLED. Форма нативная (method="post"), не AJAX-submit: успех — 302 на /cabinet.

1) Флаг в .env

  • Конфиг: config/app.php → partner_self_registration_enabled.
  • Чтение: filter_var(env('PARTNER_SELF_REGISTRATION_ENABLED', true), FILTER_VALIDATE_BOOLEAN) — строка false / 0 / off / no даёт выключено; отсутствие ключа или true — включено.
  • Дефолт: env('PARTNER_SELF_REGISTRATION_ENABLED', true) — регистрация открыта.
  • Закрыть: PARTNER_SELF_REGISTRATION_ENABLED=false.
  • Снова открыть: закомментировать строку или поставить true.
  • Если на инстансе включён php artisan config:cache, после правки .env нужно пересобрать кеш конфига. Без кеша достаточно сохранить .env. Blade view cache для этого флага не нужен.

2) Что скрывается и что остаётся

  • Кнопка «Регистрация» в десктопной шапке (#mainNav) и в мобильном меню (#publicNavDrawer, resources/views/includes/public-navbar.blade.php). Обе копии завязаны на $partnerSelfRegistrationEnabled (Route::has('partner.register') и config('app.partner_self_registration_enabled', true)), не только на наличие роута.
  • Кнопка «Войти», заявки на демо и регистрация учеников не затрагиваются.
  • Залогиненный пользователь шапки не видит гостевые кнопки: вместо них — «В личный кабинет».
  • Тот же navbar на SEO-страницах и /blog.
  • Прямой GET /partner/register при закрытом флаге отдаёт заглушку landing.partner-register-closed (200): «Регистрация временно закрыта», CTA на демо (#createOrder) и Telegram https://t.me/prukon, ссылка «Войти». На заглушке нет формы саморегистрации и нет скрипта partner_register. Layout layouts.landingPage по-прежнему подключает модалку демо (includes/modal/order.blade.php) с recaptcha action contact и $.ajax на /contact/send — это заявка на демо, не регистрация школы.
  • POST /partner/register при закрытом флаге — 403 HTML/JSON, партнёр и пользователь не создаются (StorePartnerSelfRegistrationRequest::authorize()).
  • Обе страницы (форма и заглушка) ставят <meta name="robots" content="noindex, nofollow">.

  • JSON: 422 errors.field[], те же тексты (кроме 403/429).

5) Успешная регистрация

  • Контроллер: GuestPartnerRegistrationController::store.
  • PartnerSelfRegistrationService::register() в транзакции создаёт: partners.title, email, is_enabled=true, order_by=0, registration_verified_at=null; пользователя с тем же email, ролью admin, is_enabled=true, пароль через Hash::make.
  • Сервис не пишет partners.business_type. Текст на форме («тип владельца по умолчанию: индивидуальный предприниматель, можно изменить позже в настройках») — копирайт страницы, не поле формы и не запись в БД. Тип юрлица для оплат — в юр. лицах партнёра, не в этом сценарии.
  • После Partner::created (общий observer модели, не только саморегистрация): assignBasePermissionsForPartner, LessonOccurrenceStatusesSeeder::ensureForPartner, PartnerWidgetService::ensureForPartner (строка partner_widgets), TrainerTypeCatalog::ensureSystemType.
  • Письмо PartnerSelfRegisteredNotification (очередь platform_outbound_mail, тема «Регистрация школы на kidscrm.online», заголовок X-Partner-Id).
  • Вход: Auth::login($user, false) — remember-cookie не ставится; затем $request->session()->regenerate(); 302 /cabinet.
  • reCAPTCHA формы: JS grecaptcha.execute(..., {action: 'partner_register'}), сервер GoogleRecaptchaVerifier::verifyOrFail(..., 'partner_register'). Без site_key скрипт формы не рендерится, native POST всё равно уходит (ошибка recaptcha_token required).
  • JS формы: IIFE по getElementById('partner-register-form'), e.preventDefault() пока токен пуст, затем form.submit(); не $.ajax / не fetch.
